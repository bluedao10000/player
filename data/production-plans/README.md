# 云端补集登记

在广州服务环境执行 `bin/knowledge episode-register < plan.json`。数据经校验后一次写入 PostgreSQL，两台服务在下一次轮询获取。相同内容可重复登记，已登记的分集配置和路由受不可变检查保护。只补下一集时可单独提交新一集与它使用的人物，无需重传旧集。接受原格式的本地导入命令为 `episode-plan-load`。

| 字段 | 行为 |
|---|---|
| first、last | 季内集号范围，含两端。sourceNumber 独立标记全剧集号。已有发布指针的集跳过。 |
| priority | 0–100，数字较大先领取。已在运行的任务继续完成。 |
| maxEpisodes | 该作品自启用策略以来可累计准入的集数。提高额度可继续，重复登记不会重置计数。 |
| tokenBudget、reserveTokens | 作品的准入预算和每集预留。每个已准入集占用预留与计量实耗的较大值。预算不足暂停新增集；供应商最终计量可能超过预留。已有用量可在工作台查看，计量缺失另列。 |

sourceRules 指定官方或发行方公开分集梗概的条目容器 entry、标题 heading、正文 body。标题取文本，或用 attribute 取 alt/title/content。标题与实际印刷集号必须唯一匹配。独立来源可取 wiki-episode 的分集锚点，也可用 paragraphs 配合 guideParagraphs 定位段落。稳定的 slug、人物、剧情节点和既有肖像摘要在同一份数据里登记。已登记来源站点可复用选择器；新站点需要先核对来源，新增数据格式需要解析器。

缺少配置时工作台显示缺分集配置。有配置但未出现在有效盘点的缺集继续等待。采集失败的原因和时间写入数据库，成功后保存两份带句子和摘要的快照，再进入付费文本、图片和发布验收。
