# 分集选题配置

本目录通过 Compose 只读挂载给数据服务。新增《火影忍者》集数时，在同一份 JSON 的 `episodes` 末尾追加一项，保存即可。服务每 45 秒检查配置。首次导入要求 PostgreSQL 已有相同 provider ID、作品类型与开播年份的唯一作品。《火影忍者》使用官方英文分集页，《章鱼哔的原罪》使用 TBS 动画版日文分集页，两者均与独立分集表核对。后者在目录中是 ONA。影片《蓦然回首》以 `MOVIE` 类型登记，共一个全片导读单元，剧情来源使用官网与 2024 动画电影条目。作品级配置 `type` 默认为 TV，`complete: true` 要求已完结、集数与 canonical 目录一致，按第 1 集到最后一集连续登记；读者范围仍由逐集验收决定。

| 字段 | 填写方式 |
| --- | --- |
| `number / slug / sceneSlug` | 集号、章节和场景的稳定路由标识。同一版本内分别唯一。 |
| `sourceNumber` | 官方和独立资料的集号与季内 `number` 不同才填写。《药屋少女的呢喃》第三季 `number: 1` 对应全剧 `sourceNumber: 49`，归档与 H5 仍按季编号。 |
| `official / officialTitle` | 官方分集 URL 和页面完整标题。联网时再次核对实际标题和集号。 |
| `guide / guideTitle` | 分集资料 URL，含对应的 `#epN` 锚点；标题按原大小写填写。 |
| `guideParagraphs` | B 批新闻稿取证使用。这一字段按剧情顺序列出独立分集资料的段落开头。Pi 先核对发布方的集号与标题，再从指定段落定位剧情句子。摘要与正文有重复表述时，每个后续节点从上一个节点之后匹配。 |
| `beats` | 依剧情顺序配置 4–6 个节点，覆盖 motive、turn、cause。每个 needle 选取不同原文句子中的独特短语，question 写明该段应交代什么。至少一个节点用 officialSentence 指向支持该结论的官方原文句号（从 1 开始）。 |
| `people` | 填写本集主要人物的 slug、中文名、身份及出场段号 beat。新人物也要在作品的 people 中配置一次肖像参考。 |
| `setting` | 数组第一个值是要讲清的设定用词，第二个值是有出处的段号，从 1 起。 |
| `sceneName / place / sceneBeat` | 场景名、发生地点、插图与场景回跳绑定到的段号。 |
| `art / portrait` | brief 描述画面中的人物与动作，referenceURL 为来源图片，sourceSHA 为下载字节的 SHA-256。人物参考可用 box 指定归一化的左、上、宽、高。 |

取证与校对入库后，数据服务为本集派发三张场景候选并复用同一角色的肖像任务。自动验图同时检查原图和手机裁切。工作台保留任务轮次、复核意见、五维检查以及退回原因。通过后正文、锚点与选图写入独立发布记录。读者只能沿连续完成的集数阅读。后补集数不会重抽已定稿的插画。

已登记集数的配置受锁定保护。追加前可用 `python3 -m json.tool data/episode-plans/naruto-tv-2002.json >/dev/null` 检查 JSON。数据服务会在日志中报告重复标识、来源或已登记设定发生变化等配置错误。模型密钥沿用部署的环境变量。
