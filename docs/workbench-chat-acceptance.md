# Folio 工作台对话验收

2026-11-22。验收环境为本地 Docker 与隔离 PostgreSQL 测试 schema。

## 审计与实现

| 原有入口 | 审计发现 | 本次改动 |
| --- | --- | --- |
| `EditorDesk`、`ProductionPlans` | 审稿和制作计划有独立表单，缺少持久对话 | 共享侧栏增加工作台对话。用 assistant-ui 显示会话、用 Astryx 提供确认动作。从计划和审稿任务可带上下文进入 |
| `RevisePlan` | 文字意见与部分失败媒体重排，缺少字段更新 | 新增结构化建议和确认接口。确认后更新作品、集数、预算、制作策略或暂停状态 |
| 作品库存、预算账本和媒体回执 | 记录在不同业务表和接口 | Gin 按作品、计划、分集和审稿任务读取快照。Pi 根据快照和最近对话回答，写入由 Gin 确认接口执行 |
| `sync` 与 Pi Durable | 已有盘点、规划、预算预留和生产任务 | 范围或策略变化重新进入盘点。运营暂停阻止新预算预留及已关联任务领取。原人工审稿继续负责发布相关决定 |

## API 与数据验证

- `GET /api/v1/editor/chat` 返回当前账户的会话和可选上下文。
- `POST /api/v1/editor/chat` 使用客户端生成的 `request_id`。Pi 返回回答或建议，Gin 保存字段级差异。相同请求可安全重放，重复编号携带不同内容返回冲突。
- `POST /api/v1/editor/chat/:id/resolve` 从服务端读取已存建议。事务内复核确认人、revision、预算、作品范围和定稿保护。重复确认只产生一条 `workbench_plan_operations` 回执。
- 本地开启工作台时才提供 API。H5 代理沿用回环地址检查、同源 POST 和工作台会话。测试数据和操作回执使用临时账户与计划。

| 场景 | 验收结果 |
| --- | --- |
| A 查询作品进度 | 真实 Pi 两轮对话读取《星际牛仔》本地库存与制作状态，第二轮识别上一轮作品与版本 |
| B 修改分集范围 | 真实 Pi 生成第 8–8 集到第 8–10 集的差异，浏览器确认后 PostgreSQL 精确写入 |
| C 修改预算 | 同一真实对话由 60,000 改为 1,000,000 token，确认后入库 |
| D 修改人物一致性 | 真实 Gin 和隔离 PostgreSQL 测试通过。人物一致性写入 `production_policy`，策略随下一次规划传给 Pi |
| E 暂停和恢复 | 隔离库验证独立字段、revision 与重复确认；生产领取与预算入口读取暂停状态 |
| F 失败分集重试 | 隔离库验证失败取证任务的 policy 增一，使其重新符合调度条件 |
| G 展示差异 | Docker 浏览器确认前可查看字段级差异 |
| H 确认、入库与触发 | Docker 浏览器确认后验证 PostgreSQL 的范围、预算、revision 和单条审计。API 测试验证范围改动将状态设为 `inventory` |
| I 刷新后保留记录 | Docker 浏览器分别在确认前和确认后刷新，确认卡和执行结果均保留 |
| J 未确认无制作副作用 | 隔离库验证待确认和取消时业务字段、revision 无变化。同时覆盖重复确认、旧版本冲突和禁止覆盖正式内容 |

隔离 API 测试使用确定性 Pi 回包，实际执行 Gin、SQL、事务和迁移。真实模型与浏览器走本地 Docker 独立验收。可用 `KNOWLEDGE_TEST_DATABASE_URL` 指向测试数据库并运行 `go -C apps/api test ./internal/handler/knowledge -run TestWorkbenchChatConfirmation -count=1`。

## 当前边界

- 未登记来源配置的新增分集可进入盘点与规划，后续仍由现有分集配置登记流程接管。本次验收未启动新增分集出图或发布。
- 单集重试处理已登记的失败取证或可重排媒体步骤。单集重建面向未发布分集的取证与写作，批量重建及覆盖正式内容尚未接入对话。正式发布沿用人工审核入口。
- 计划已有用量时更换作品需新建计划。缩小范围须保留已经登记在该计划下的分集。已发布分集排除在重新盘点的缺口之外。
