# 架构治理工作账

基线：`8ebd9d2`，2026-11-28，从已提交版本独立检出。此页记录跨模块决策、验证与任务池，不定义第二套接口或生产现状。产品、模块依赖图和部署边界分别以[产品架构](产品架构.md)、[技术架构](技术架构.md)、[图源目录](diagrams/README.md)为入口。历史工作台图不是现行前端，目标部署不是现网证据。

## 改一个概念，先找哪一方

| --- | --- | --- |

| sync 定时器 → Go 知识库服务 → Pi Durable → Go 验收事务 | PostgreSQL 持有来源、候选、验收、发布；Pi SQLite 只负责恢复执行。调用回执从 outbox 重放到用量账本 | 轮询同一任务、重投同一回执、重新发起计费调用是三件事。参见[生产链](diagrams/current.html)与[模型用量](模型用量与计费.md) |

## 已验证的批次与决策

- **图源校验不依赖渲染产物。** 基线的 `python3 docs/check.py` 在干净检出因缺少 `technology.svg` 退出。恢复提交派生文件会重新引入双写，给 Python 自建 Mermaid 解析器又会漏掉隐式节点。保留 Python 离线验链；CI 复用已有浏览器与同一渲染器，直接对所有 `.mmd` 执行 `--check`，不产生文件。实测 10 张源图通过，临时增加无证据的连线端点则失败。

- **计费调用身份归用量模块。** 配置调度与 API 均调用 `modelusage.NewID()`；保留领取后创建、预留与结算复用同一 ID 的语义，不动已持久化的 ID 或业务重试。Go 1.25 的 `crypto/rand.Read` 不返回可恢复错误。用量模块的格式与唯一性用例、调度包测试和独立复审通过。

- **两组已共享的 SQL 按事实归属。** `reader.LockReader` 供读者计划、会员下单和 StoreKit 入账共用；`ops.SeedOpsMediaBatchWorlds` 供分集登记、世界导入和 ops 测试共用。调用仍在原事务内；历史迁移中的 SQL 不追改。`TestSharedQueryOwners` 检查这两个查询正文不在其他运行时或 fixture 资源重复，不禁止其他同文异义 SQL。隔离 PostgreSQL 上 8 个定向测试通过。

- **CI 显式执行数据库契约。** 同一 `npm run check` 在 CI 连接临时 PostgreSQL 17；动态端口、逐用例临时 schema、Go 包串行，不依赖开发者数据库或密钥。隔离容器上先运行全量 API 基线，再运行修改后的根检查，均通过。未在 GitHub 托管 runner 上实跑。

- **五处 Gin 地址选择共用一个默认值。** [shared 知识客户端](../packages/shared/knowledge.ts)提供 `serverKnowledgeApiUrl()`，Vite 开发代理、两种账户代理、非旧商户通知和服务端知识读取在使用时取值。浏览器仍走同源，旧商户出口、cookie/Bearer、响应头和错误码各自保留。根检查覆盖默认、覆盖与浏览器同源三种行为；本次构建的静态站与读者适配器通过隔离网关（Gin fixture、实际图片服务）的 390px 章节、场景回跳、iOS JSON、OAuth 与支付转发用例。未发起真实付款或调用线上接口。

- **原生阅读投影归实际发布者。** 两个 Web 入口过去均依赖 iOS 目录，该目录又导入 Web 图片与原创目录。把投影留在 iOS 并抽出公共 UI 包会扩大依赖；直接迁回既有 reader 目录则可删除镜像的跨应用 `COPY` 和白名单，不加转发层。Swift 仍通过 `/ios-data/v1` 读取。迁移前后用相同 390px 与网关契约测试通过，无 Swift 工程、响应结构或图片地址变更。[导入门禁](check-imports.mjs)用已安装的 TypeScript 解析真实静态边；检查时的 81 个模块、193 条边无环，不允许应用间或 shared 到应用实现的静态导入。临时负例分别验证了模块环、跨应用引用和 shared 指向扫描根外应用文件都会失败，纯类型回边可通过。

- **通用章节按一处规则选段落，两端分别呈现。** [段落选择](../apps/web/src/features/reader/chapter-reading.ts)优先使用定稿（包括显式空数组），无定稿时按顺序选研究段和带锚点的原文，无研究时保留全部原文。两个使用方都由 Web 工程发布，不扩大 shared 的对外契约。H5 保留独立导读、场景侧栏、插画和历史 DOM 锚点；原生阅读 API 保留扁平 `blocks`。H5 命中原创目录仍直接读原稿。迁移前后以[同一组 SSR / iOS 响应夹具](../apps/web/test/chapter-reading.test.mjs)验证以上分支，已纳入根检查；[390px 烟测](../deploy/gateway/tests/browser.cjs)另走原创回跳和旧研究章节的主、副锚点。

- **归档根目录共用配置，失败策略按调用方保留。** [ArchiveDir](../apps/api/internal/config/config.go)先取非空 `KNOWLEDGE_ARCHIVE_DIR`，否则取用户配置目录下的 `tidepost/knowledge-archive`。无法定位用户目录时，[来源快照](../apps/api/internal/service/knowledge/archive.go)仍报错，[模型回执](../apps/api/internal/service/modelusage/spool.go)仍使用相对于进程工作目录的 `tidepost/knowledge-archive/model-usage-outbox`。不迁移已有文件；发布命令原本只读显式环境变量，不引入用户目录回退。[兼容测试](../apps/api/internal/handler/knowledge/model_usage_test.go)验证绝对与相对覆盖、默认与失败分支；在临时工作目录预置旧回执，隔离 PostgreSQL 两次重放后仍只记一笔，成功后清空回执。

- **Agent 只合并计量单位相同的请求体。** 媒体（4096 B）、规划（100000 B）、取证（160 KiB）、工作台（256 KiB）使用[同一字节读取函数](../apps/agent/src/request-body.ts)，先限长再解码 UTF-8；413 仍在退出请求迭代前发出。ACK 按字符串长度，分集配置按已解码文本的字节数，保留两者原有协议。已在临时副本验证受影响的 `server.ts` 改动可与原工作区已有修改无冲突地三方合并；不写原工作区。工作台真实 HTTP 边界和分块 UTF-8 纳入 Agent 单测。

- **锁号按真实互斥对象治理。** 验证码签发只操作邮箱配额，默认继续用 `82045102` 兼容旧实例，整库显式切到 `v2` 后才用独立键 `82045138`。知识库投影、归并与治理继续共用 `82045102`；发布接收与登记均检查并写入分集事实，必须共用 `82045125`。两连接[并发用例](../apps/api/internal/repository/database/advisory_lock_test.go)在 PostgreSQL 17 上验证阻塞与独立性。新版本不会自动启用新协议；启用和回滚的停写与重连条件见[运维手册](运维手册.md#数据库事务锁验证码签发与知识库投影)。

- **跨工作目录恢复只读取明确指定的位置。** `KNOWLEDGE_LEGACY_USAGE_OUTBOX` 指向旧 outbox 本身的绝对路径，供同一账本的 sync 重放；不改变新回执的写入位置，也不搜索文件系统。单节点分别尝试活动与旧目录；分 lane 时只由显式配置的 research 进程读文件，media 继续只拉 Pi 回执。路径错误报告到 usage 循环，成功入账才确认文件。隔离库验证换工作目录、重送同一回执仍只入账一次、失败文件保留、另一目录仍可入账。挂载及一次性恢复命令见[模型用量与计费](模型用量与计费.md)。

## 任务池与边界

本轮登记的治理项已处理。生产切换锁协议、挂载或导入实际回执是独立运维操作，不是本分支提交的副作用。

验收范围以实际执行记录为准。隔离库、fixture 和只读源码审计不代表已在生产验证；不自动部署、合并或迁移生产数据。
