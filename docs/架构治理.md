# 架构治理工作账

基线：`8ebd9d2`，2026-11-28，从已提交版本独立检出。此页记录跨模块决策、验证与任务池，不定义第二套接口或生产现状。产品、模块依赖图和部署边界分别以[产品架构](产品架构.md)、[技术架构](技术架构.md)、[图源目录](diagrams/README.md)为入口。历史工作台图不是现行前端，目标部署不是现网证据。

## 改一个概念，先找哪一方

| 业务路径 / 依赖方向 | 谁写事实；谁持有派生状态 | 改动时不可混淆的约束 |
| --- | --- | --- |
| H5 loader → shared → Gin → 发布视图；SwiftUI → iOS 适配器 → 同一公开契约 | Go 冻结章节与选图；浏览器和 Swift 只投影，iOS 另有扁平段落模型 | 作品 UUID、slug、段落 key、内容地址稳定。原生、浏览器的回跳都要测。见[阅读适配](../apps/ios/server/reader.server.ts)与[投递核验](../apps/sync/cmd/reader-release/send.go) |
| H5 cookie 代理 / iOS Bearer 代理 → Gin reader → PostgreSQL | 账户书架和进度由 [reader SQL](../apps/api/internal/repository/queries/reader/library.queries) 决定；访客本地记录、原生离线队列另有生命周期 | 书签与进度冲突处理不同；不统一两端鉴权、写队列或进度百分比。公开缓存与私有账户响应分开 |
| 独立工作台 → Gin workbench → 服务 / SQL；Gin → Agent → Gin SSE | 审批修订、审计和可回放事件由 [Gin 工作台](../apps/api/internal/handler/workbench) 持久化；Agent 输出不是已批准决定 | 校验版本和身份；独立前端不在本仓，不能据此声明其缓存或 UI 通过了验收 |
| sync 定时器 → Go 知识库服务 → Pi Durable → Go 验收事务 | PostgreSQL 持有来源、候选、验收、发布；Pi SQLite 只负责恢复执行。调用回执从 outbox 重放到用量账本 | 轮询同一任务、重投同一回执、重新发起计费调用是三件事。参见[生产链](diagrams/current.html)与[模型用量](模型用量与计费.md) |
| 发布发送端 → 接收端 → 正式读库与图片服务 → Nginx → 读者 | 发布授权和指纹由 Go 与 PostgreSQL 决定；[图片服务](../apps/image/README.md)管理资产目录、字节和衍生件，网关缓存不是授权 | 图像副作用不随数据库回滚；不能把制作库和读库、公开和签名图、缓存失效和内容寻址合并 |
| Go cmd → 配置 / Zap → handler、scheduler → service → 命名查询 / 迁移 | API 和 sync 各自构建，复用 Go internal 包；[SQL 边界测试](../apps/api/internal/repository/database/sql_boundary_test.go)禁止业务 SQL 回流 Go 字符串 | 保留业务事务和物理连接的边界。HTTP 日志、worker 心跳、业务审计分别回答不同问题 |

工具链入口：[根检查](../package.json)、[CI](../.github/workflows/check.yml)、[原生验收](../apps/ios/README.md)、[图片服务测试](../apps/image/tests)、[网关验收](../deploy/gateway/tests)。Go 编译器拒绝包循环；这不证明 TS 导入图无环。界面文案由[文案规范与检查](界面文案规范.md)维护，视觉表现仍由 H5 与 SwiftUI 各自负责。

## 已验证的批次与决策

- **图源校验不依赖渲染产物。** 基线的 `python3 docs/check.py` 在干净检出因缺少 `technology.svg` 退出。恢复提交派生文件会重新引入双写，给 Python 自建 Mermaid 解析器又会漏掉隐式节点。保留 Python 离线验链；CI 复用已有浏览器与同一渲染器，直接对所有 `.mmd` 执行 `--check`，不产生文件。实测 10 张源图通过，临时增加无证据的连线端点则失败。

- **计费调用身份归用量模块。** 配置调度与 API 均调用 `modelusage.NewID()`；保留领取后创建、预留与结算复用同一 ID 的语义，不动已持久化的 ID 或业务重试。Go 1.25 的 `crypto/rand.Read` 不返回可恢复错误。用量模块的格式与唯一性用例、调度包测试和独立复审通过。

- **两组已共享的 SQL 按事实归属。** `reader.LockReader` 供读者计划、会员下单和 StoreKit 入账共用；`ops.SeedOpsMediaBatchWorlds` 供分集登记、世界导入和 ops 测试共用。调用仍在原事务内；历史迁移中的 SQL 不追改。`TestSharedQueryOwners` 检查这两个查询正文不在其他运行时或 fixture 资源重复，不禁止其他同文异义 SQL。隔离 PostgreSQL 上 8 个定向测试通过。

- **CI 显式执行数据库契约。** 同一 `npm run check` 在 CI 连接临时 PostgreSQL 17；动态端口、逐用例临时 schema、Go 包串行，不依赖开发者数据库或密钥。隔离容器上先运行全量 API 基线，再运行修改后的根检查，均通过。未在 GitHub 托管 runner 上实跑。

## 任务池与边界

| 项目 | 已有证据 / 下一项判据 |
| --- | --- |
| Agent 请求体 | [三个内部 POST 入口](../apps/agent/src/server.ts)重复按字节限长，阈值不同；ACK 路径按字符串长度。主工作区正在改该文件，等该改动落定再合并，先测恰好到限、超一字节、分块与非 ASCII |
| 通用章节回退 | H5 与 iOS 都优先 `reader_passages`，但 H5 单独渲染 research、aside、DOM anchors；仅在缺失、空数组、旧研究段落和原创例外都有双端 fixture 后收敛，不能简单摊平 |
| 待读者配置核对 | 浏览器同源，账户与付款代理用服务端地址，历史商户通知另有固定出口。只应共享服务地址默认值，不共享凭据或重定向语义 |
| 待确认：锁命名空间 | 验证码与知识库投影均使用 `82045102`；发布接收与计划登记均使用 `82045125`。分库和同库部署下效果不同。先核对旧实例、混合版本和并发约束，再决定是否拆锁；不把同文 SQL 一律判重 |
| 待确认：归档目录异常 | 来源归档返回 `UserConfigDir` 错误，用量回放会回退到相对路径。统一路径前需确定已有回执恢复策略，不移动文件或改变失败语义 |

验收范围以实际执行记录为准。隔离库、fixture 和只读源码审计不代表已在生产验证；不自动部署、合并或迁移生产数据。
