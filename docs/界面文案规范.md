# 界面文案规范

适用于 H5 读者端（[阅读与角色](../apps/web/src/features/post)、[读者账户](../apps/web/src/features/reader)、[作品世界](../apps/web/src/features/worlds)、[路由与页面标题](../apps/web/src/routes)）、[iOS 读者端](../apps/ios/Folio)和[编辑与数据工作台](../apps/web/src/features/workbench)。Web 与 iOS 各自维护字符串，没有共享词表，所以两端用词以本文为准。新增或修改界面文字时，先查术语表，再按句式和标点写。本文依据 2026-11-22 的全量文案评审整理，尚未修正的偏差见文末。

## 读者与口吻

| 界面 | 面向 | 写法 |
| --- | --- | --- |
| 读者端 | 匿名或已登录的读者 | 称「你」，不用「您」。功能文字短而直白，说清结果和下一步。剧情、角色手记、角色关系可以写得文学化，人物设定以正文为准 |
| 工作台 | 运营与编辑 | 可使用下方工作台术语，状态要能和数据库记录对上。不写加载策略、接口名等实现细节 |

读者端不展示开发阶段的状态。「待配置」「尚未生效」「入口尚未开放」这类情况，应直接隐藏入口；确实需要说明时，写清读者现在能得到什么。

## 读者端术语

| 统一用词 | 常用搭配 | 读者端不再使用 | 说明 |
| --- | --- | --- | --- |
| 作品 | 作品世界、作品目录、作品知识库 | — | 作品名在句子中加《》；卡片标题、面包屑、标签中不加 |
| 版本 | TV 版、剧场版、全片 | — | 搜索提示等首次出现处给出示例。「全片」只用于电影类版本 |
| 角色 | 角色图鉴、角色关系、出场章节、本幕角色 | 人物、登场角色、在场人物、人物关系 | 工作台里的知识维度仍称「人物」 |
| 章节 | 量词用「篇」；有集号时写「第 N 集」。H5 分集导读末尾写「下一集 · 标题」，iOS 章节末尾写「下一篇 · 章节标签」 | 下一章 | 集号放在章节标签里，由数据给出，界面不按标签文字判断 |
| 场景 | 故事中的场景、相关场景、本章场景 | 用「这一幕」作区块标题 | 「幕」只在剧情互动内部使用，如「本幕完」 |
| 导读 | 分集导读、全片导读 | — | |
| 书架 | 加入书架、移出书架、已加入书架、我的书架 | 收藏、我的收藏、收藏章节，以及单独使用的「移除」 | 合并提示写「N 篇书架章节」 |
| 阅读进度 | 已读 N%、同步书架和阅读进度 | 阅读位置，以及单独作标签的「进度」 | |
| 阅读记录 | 本机阅读记录 | — | 只指本机书架加阅读进度这个整体，用在访客页和首次登录导入 |
| 继续阅读 | 区块标题用「继续阅读」，按钮用「接着读」 | 最近读过 | |
| 剧情互动 | 入口按钮「进入剧情」，选项叫「行动」，结束时显示「本幕完」 | 剧情试玩、私人剧情、角色剧情、角色互动、预设分支 | 将来的角色聊天另行命名，不复用这个词 |
| 回到章节 | 从场景、剧情回到出处 | 回到故事、回到原文、返回阅读 | 按钮可以带上章节名：「回到章节 · 标题」 |
| 读者账户 | 登录、退出登录、绑定微信、绑定邮箱、更换邮箱 | 我的读者账户、读者服务、会话、凭据 | |
| 邮箱、验证码 | 字段标签写「邮箱」「验证码」；说明写「6 位验证码，5 分钟内有效」 | 电子邮箱、六位验证码 | |
| 会员档位 | Free、Plus、Pro；付费档写「Plus 会员」「Pro 会员」，免费档只写「Free」 | Free 会员 | 档位名称和每期积分从同一份配置读取，iOS 不写死 |

| 购买 | 按钮写「购买」「去支付宝支付 ¥20」；订单状态为待付款、已付款、已退款、已关闭 | iOS 订单状态里的「已购买」 | 「恢复购买」沿用 App Store 的系统叫法 |

## 工作台术语

| 术语 | 含义 | 注意 |
| --- | --- | --- |
| 工作台 | 编辑与数据工作台的整体。页面标题用全称，导航和按钮里写「工作台」 | 不用「内容工作台」 |
| 运营总览 | 工作台首页，集中展示作品、知识资产、执行和关注指标 | 不按页面记录窗口计算指标 |
| 运营拓扑 | 工作流定义与运行日志页面 | 节点定义与实际任务数分开表达 |
| 知识资产 | 作品知识库存、分集验收和图片候选页面 | 知识计数分项展示，不合并成总数 |
| 项目 | 分集制作计划、补集队列、发布记录和作品用量页面 | 保留原计划、准入和发布行为 |
| 运营分析 | 制作用量和备份回执页面 | 趋势分析在 Phase 4 提供 |
| 异常与决策 | 展示离线进程、阻塞、等待人工和失败执行；可进入编辑审稿 | 关注列表不是持久异常台账 |
| AI 助手 | 工作台对话入口 | 保留变更提案、确认和审计 |
| 在线工作进程 | 最近成功心跳仍在在线阈值内的进程数 | 连续错误的进程仍计入在线，并单独提示 |
| 运行中执行实例 | Agent 心跳报告的非终态执行数量 | 和「当前执行任务」分别显示 |
| 等待队列、当前阻塞、等待人工 | 分别对应 pending、blocked、waiting_human | 状态与数据库映射一致 |
| 需要关注 | 按严重程度排序的工作进程、待处理项和近 24 小时失败 | 总览最多展示 20 条；异常页展示完整列表 |
| 未登记 | `works.type` 为 NULL 的作品类型分组 | 单独展示，不并入其他作品类型 |
| 取证 | 联网收集来源并保存快照 | |
| 起草、自检、待审核、退回、批准并发布 | 编辑任务的各个阶段 | |
| 定稿 | 已批准的版本 | |
| 五维验收 | 检查一集在人物、剧情、世界观、时间线、图片五个维度是否完整 | 和「五项验图」是两件事，不能混用 |
| 五项验图 | 对单张候选图做视觉检查：人物一致、场景与动作、五官与手部、画面干净、手机构图 | |
| 范围验收 | 对选定集号范围做的验收记录 | |
| 候选、原图、手机裁切、槽位 | 图片资产的组成和存放位置 | 只在工作台使用 |
| 返工：重绘、重裁、复验 | 原图有问题就重绘，裁切有问题就重裁，改完复验 | |
| 补集、盘点、缺集 | 自动补齐分集的队列和库存快照 | |
| 回执 | 运行、模型调用、发布时留下的记录 | 只在工作台使用 |
| token | 模型用量单位。小写，前后各留一个空格 | 预算统一写「token 预算」 |

每个步骤 key 对应唯一的中文标签，不同 key 的标签也不能重复。区块上方的英文小标题（如 `MEDIA ASSET MANAGEMENT`）是工作台的视觉样式，可以保留，但关键信息要同时出现在中文标题或正文里。

## 状态词

| 类别 | 统一用词 | 不再使用 |
| --- | --- | --- |
| 任务运行 | 等待执行、执行中、成功、失败，以[状态表](../apps/web/src/features/workbench/shared/format.ts)为准 | 进行中、处理中、任务失败 |
| 验收与验图 | 通过、未通过；需要说明去向时写「退回重绘」「退回重裁」 | 验图通过、五维通过（作状态标签时） |
| 订单 | 待付款、已付款、已退款、已关闭 | 已购买 |
| 跳过 | 跳过，并附上原因 | |

## 句式

| 场景 | 写法 | 示例 |
| --- | --- | --- |
| 加载中 | 正在 + 动作 + 一个省略号字符「…」 | 正在打开书架… |
| 加载失败 | 先说现状，再配一个「重试」按钮 | 书架暂时没有载入。〔重试〕 |
| 操作失败 | 「X 失败，请重试。」 | 保存失败，请重试。 |
| 操作成功 | 直接写结果状态，不加感叹号 | 已加入书架 |
| 空状态 | 现状 + 怎样填满 + 一个入口 | 书架还空着。在章节里点「加入书架」，就能在这里重读。〔去找故事〕 |
| 按钮 | 以动词开头，2–6 字，不加标点 | 获取验证码、接着读、绑定微信 |
| 确认选择 | 每个选项写明后果 | 合并到我的账户；跳过，仅保留在本机 |
| 倒计时 | N 秒后可重新发送 | 42 秒后可重新发送 |

内容没有载入时用「重试」，读者主动拉取最新状态时用「刷新」，不用「重新载入」「重新连接」。读者端的错误提示不展示 HTTP 状态码，排障信息记到日志里。

## 标点与格式

- 使用全角中文标点。完整的句子以句号结尾；标题、按钮、标签、选项和 Tab 不加句末标点。
- 中文与英文、数字之间留一个空格，如「第 3 集」「5 分钟」「AI 场景插画」。数字与 %、¥ 之间不留空格。
- 数量和时长用阿拉伯数字。叙事正文里的固定说法除外，如「一封信」「两幕」。千分位用 `toLocaleString('zh-CN')`。
- 分隔符用「 · 」，前后各一个空格。区间用短横「–」，如「第 1–26 集」。
- 作品名、章节名用《》，引用界面元素用「」，角色台词和引语用“”。
- 站内跳转用「→」，外部链接用「↗」，返回用「←」。
- 读者端日期写作「2026年11月22日」，按北京时间显示。工作台也统一用北京时间，格式为「2026-11-22 15:26」；必须显示 UTC 时要标注「UTC」。
- 品牌名写作「Folio 时光」，中间有空格。页面标题统一用 [siteTitle](../apps/web/src/site.ts) 生成「页面名 · Folio 时光」。

## 工程约定

- 文案不参与逻辑判断。导航高亮由页面传入 `NavKey`（`discover`、`works`、`cast`、`stories`、`me`，见 [Layout](../apps/web/src/features/post/design.tsx)）；电影类版本看作品卡片的 `format`（`film` / `series`，由迁移 058 按作品的规范类型生成），不要解析 `edition_label` 的文字。
- 缺数据时不用某部具体作品的名称来兜底。
- 订单、任务、验图的状态映射各维护一张表，Web 和 iOS 的文字保持一致。
- [文案检查](copy-check.mjs)是根目录 `npm run check` 的第一步，也可以单独运行 `npm run check:copy`。它在读者端代码里查找术语表中已停用的说法，在工作台代码里查找 UTC 时间显示，还会查找根据 `edition_label` 文字或中文导航标签做判断的代码。每处问题都会列出文件、行号和应改用的写法。确实需要保留的行，在行尾加注释 `copy-check: allow`。术语表新增停用说法时，同步更新这个脚本的规则。

## 已知偏差

2026-11-22 的评审偏差已全部处理：H5 与 iOS 用词按本规范统一，工作台改为北京时间，积分取整，隐藏 iOS 中尚未就绪的入口，船长统一为「他」，删去「积分消费入口尚未开放」，移除不属于本项目的本机资料迁移页；iOS 档位积分改为读取会员接口，导航高亮与「全片」判断不再依赖中文文字。新发现的偏差记在这里，并链接到对应文件。
