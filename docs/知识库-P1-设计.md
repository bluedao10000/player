# 知识库 P1 设计

本文保留旧工作台的实现与验收记录。当前状态见[功能地图](功能地图.md)。

核验基线为 `main`、HEAD `91e92da` 及本地 Phase 3、P0 工作区。本文记录已执行的核验及待评审方案。P1 聚焦身份治理、来源更新提示、跨作品只读能力，不引入通用 Entity、独立 Assertion 表、全量知识图谱、向量库、图数据库或新服务。

## A. 身份合并和拆分

### 入口和写事务

管理 API 为 `POST /api/v1/admin/knowledge/actions`。请求用 `candidate_id` 选择合并候选，拆分用 `record_id`，可附 `work_id` 指向历史原作品。Go 要求操作者和理由。处理器将 `pgx.ErrNoRows` 映射为 404，其余治理错误为 409，提交成功为 204。当前服务代码的正式调用入口是该路由。[路由](../apps/api/internal/handler/knowledge/curation.go#L68) · [请求类型](../apps/api/internal/model/knowledge/decision.go#L10)

| 步骤 | 合并 `merge` | 拆分 `split` |
| --- | --- | --- |
| 起事务 | `pgx.BeginFunc`，取事务锁 `82045102`，建临时 `affected(work_id)` | 同左 |
| 解析 | `MatchPair` 要求仍存在的候选、活跃来源记录及活跃目标作品。来源记录的当前作品为 `from`，候选作品为 `to` | `ActiveRecordWork` 要求记录活跃。指定原作品时从历史 `approve/merge` 审计查验记录及去向。省略时 `CloneWork` 在 `works` 插入新 UUID，仅复制标题 |
| 选择和移挂 | `FindDecisionRecords` 取 `from` 下全部记录，包含停用记录。对这些记录 upsert `knowledge_identity_pins`，更新 `knowledge_source_records.work_id` | 只移挂选中记录，写相同 2 张表 |
| 投影和审计 | 对两侧重新选择 canonical 字段、更新 `works`，无活跃贡献一侧置为 `active=false`。删除并重建两侧的标题、来源、标签、制作方、出品方、关联 URL、播出表。全局对账 `knowledge_match_candidates`。最后插入 `knowledge_curation_actions` | 同左 |
| 失败 | 任一步骤返回错误即回滚 | 新 UUID、移挂、投影、审计同一事务回滚 |

`approve` 复用同一路径移动单条记录。若刚好移走最后一条，也会触发停用。`rematch` 删除 pin 和 rejection，随后投影，本次调用没有 `MoveRecords`。后续同步的匹配仍可能重新分配。当前校验也允许从审计中复原已停用的原作品，即便旧作品有世界。SQL 没有按世界、发布或制作事实进行拦截。[治理实现](../apps/api/internal/service/knowledge/curation.go#L18) · [治理 SQL](../apps/api/internal/repository/queries/knowledge/curation.queries#L1) · [投影 SQL](../apps/api/internal/repository/queries/knowledge/queries.queries#L66)

## B. 来源更新

### 当前写入和触发

1. `apps/sync` 调用 Go `Sweep`。AOD 用 GitHub Release 资产 ID、尺寸和 SHA-256，bangumi-data 用同源 npm tarball、入口和 SHA-512 SRI。Go 校验资产、解析和归档，再提交 staging。来源锁防同源并发，最终归并与治理共用 `82045102`。[调度](../apps/sync/internal/service/scheduler/sync.go#L161) · [来源探测及校验](../apps/api/internal/service/knowledge/upstream.go#L52) · [导入](../apps/api/internal/service/knowledge/sync.go#L193)
2. 同一 `(source_id, record_key)` 的 JSONB `raw` 或 `norm` 有差异即更新，分配到不同作品也计为更新。新记录及恢复的记录计创建，源内缺失的活跃记录转停用。事务写版本与归档信息、来源记录、目录投影、匹配候选、同步计数和来源当前版本。内容不变的行也可滚动 `version_id`，因此仅凭版本滚动无法判断记录内容变了。[版本与计数](../apps/api/internal/repository/queries/knowledge/sync.queries#L56) · [差异和归并](../apps/api/internal/repository/queries/knowledge/queries.queries#L1)
3. AOD/npm 导入事务没有调用 `Quality` 或 `RecalculateCompleteness`，没有分集失效或复核标记。长驻同步循环随后独立尝试 `QualityIfDue`，上次成功在 6 小时内或失败在 15 分钟内会跳过。到期先重算质量，再重算当前公开版本的完整度。 `--once` 在质量调度前返回。管理端 `POST /quality` 直接执行目录质检，当前不连带执行完整度重算。[调度逻辑](../apps/api/internal/service/knowledge/quality_schedule.go#L15) · [执行间隔](../apps/api/internal/repository/queries/knowledge/quality_schedule.queries#L7) · [手动质检](../apps/api/internal/handler/knowledge/curation.go#L21)
4. `world-original/world-enrichment` 是另一条 `importWorld` 路径，写来源版本、部分来源记录、世界图和发布指针。首次明确把世界导入、清单和接收端发布排除出 AOD/npm 标记触发，避免拦截现有的有意发布路径。归档 `rebuild` 走导入回放，`project` 重新投影，显示复核时应区分实时同步和维护操作。[分流](../apps/api/internal/service/knowledge/sync.go#L90) · [世界导入](../apps/api/internal/service/knowledge/world_import.go#L149) · [重投影](../apps/api/internal/service/knowledge/history.go#L75)

## D. 设计

### 1. 守住受保护作品的身份

- 在 `Decide` 的事务里先解析参与者，使用现有事务锁，按 UUID 顺序锁定对应 `works` 行。先读保护事实，再执行 `CloneWork`、pin、移挂或投影。任一参与者有 `work_worlds` 或 `world_releases` 即拒绝。前者已覆盖有外键的制作请求、计划、验收和回执。历史版本用后者兜底。对逻辑 slug 或孤儿数据做一次上线前只读盘点，能通过版本或 slug 确认归属才纳入保护。继续复用候选活跃和历史审计校验。
- 同样拦截 `approve` 的真实移挂。对受保护记录的 `rematch` 拒绝撤 pin，若日后开放需同时保证自动归并不会重分配该记录。自动同步在保护锁内保留受保护作品的现有来源归属，冲突保留给人工候选。拒绝场景返回类型化 409 和稳定原因码 `work_identity_protected`。界面提示「此操作涉及已建立作品世界、已有知识版本或已有制作计划的作品。请在工作台查看相关记录后处理。」详情可带受保护作品 UUID、slug 和原因，内部日志保留请求身份。正常审计仅在成功提交时写入。
- 第一批无需迁移。对已错位的旧数据先盘点、标出证据并交给受控修复，查 `works.active`、当前版本、审计、历史发布凭证和读库验证。受控流程需预演并核对既有公开 UUID、slug、版本、段落回跳和图片 SHA 后才可实施。本轮没有执行数据修复。

### 2. 追加来源更新复核标记

- 推荐新增一张小型工作台表。现有 `knowledge_quality_issues` 以作品和规则为键，扫描会先批量关闭 open issue，且有全局质量计数。 `ops_work_items` 是视图，会参与等待/阻塞拓扑语义。两者都无法独立存储多个来源记录及分集级复核生命周期。已有每集验收状态、完整度状态和拓扑六态继续按原合同读取。
- AOD/npm 正常导入在 Go 已有事务中，用 `incoming/assignment/removed` 的实际差异生成标记。可用现有嵌入 SQL 批量写入，保留记录 ID 和当次 run、版本及变化类型。首轮标记规范字段变化、撤回、恢复或来源标识冲突。纯 raw 差异只在影响已选取字段或受信来源链接时标记，候选告警和版本仅滚动均不计。身份冲突涉及两侧已建世界时，两侧均记录原因；根据保护规则，实际归属仍可保持原处。重试失败随同步整体回滚。历史回放不制造实时提醒，操作员可在维护环境核对差异。
- 首轮对 AOD/npm 标世界级「来源有更新」。只有存在结构化集号和确切的来源依赖证据时，在同次事务写对应 topic 的「来源待复核」；核对 `world_slug/topic/number` 与旧证据。接受同 URL 的合并证据仅限可核验的同份文档、定位及旧摘要，随后证实该集使用的段落或句子发生变化。世界级变化和集号范围推测可带供人工查看的值。已冻结验收的证据需从关联研究运行读取。首轮没有可靠分集依赖时，矩阵只在页头提示该作品来源更新，避免把所有已发布集标成待复核。
- 标记写入本身只写工作台表。AOD/npm 投影需另有保护使公开维持可达、格式稳定。推荐在外部目录同步的受保护世界投影上保留会导致公开状态翻转的当前 `active` 与决定 `format` 的类型分类，保存提议值供人工复核。其余目录字段可正常更新。独立的发布流程负责有意变更世界版本、正文、锚点和图片。实现前用公开接口验证这两个字段确实覆盖当前世界读模的直接依赖，并覆盖换类、最后活跃来源撤回、重放和原本 inactive 的遗留世界。对此前停用的世界保持原状态，另走遗留修复。原始来源与版本继续完整保留。
- 知识中心显示「来源有更新」的作品数与筛选。作品详情显示来源、旧/新版本、变化字段、更新时间、范围及「确认已核对」。只有能定位分集时矩阵行才显示「来源待复核」，已发布标志、发布回执和完整度状态保留。Go 审核接口记录操作者、时间和结果，可选择已核对或安排后续修订。以最新 `last_run_id` 做比较更新，新事件发生后旧页面确认返回 409，文案「来源已有新更新，请刷新后再核对。」后续有新定稿时，仅在其明确引用该变更的新证据且通过现有发布验证的情况下考虑自动关闭。首轮推荐由人工关闭，质检、重新盘点或普通通过验收都不会自动关闭。
- 最新迁移是 `062.sql`。拟用 `063.sql`，实施前核对有无并行占号。只追加迁移版本，标记上线从下一次实时导入开始。历史数据无需回填。以 `(world_slug,source_record_id,topic)` 聚合未完成复核，按 last run 更新；可追溯粒度为最近一次变更及处置，来源原件和批次历史继续利用既有归档。

```sql
CREATE TABLE knowledge_source_review_marks (
  id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  world_slug text NOT NULL REFERENCES work_worlds(slug),
  source_record_id bigint NOT NULL REFERENCES knowledge_source_records(id),
  topic text,
  last_run_id uuid NOT NULL REFERENCES knowledge_sync_runs(id),
  previous_version_id bigint REFERENCES knowledge_source_versions(id),
  source_version_id bigint NOT NULL REFERENCES knowledge_source_versions(id),
  changes jsonb NOT NULL CHECK (jsonb_typeof(changes) = 'object'),
  updated_at timestamptz NOT NULL DEFAULT now(),
  resolved_at timestamptz,
  resolved_by text,
  resolution text,
  FOREIGN KEY (world_slug,topic) REFERENCES episode_plans(world_slug,topic),
  UNIQUE NULLS NOT DISTINCT (world_slug,source_record_id,topic),
  CHECK ((resolved_at IS NULL AND resolved_by IS NULL AND resolution IS NULL)
      OR (resolved_at IS NOT NULL AND resolved_by IS NOT NULL
          AND resolution IN ('reviewed','follow_up') AND resolution IS NOT NULL))
);
CREATE INDEX knowledge_source_review_marks_open
  ON knowledge_source_review_marks(world_slug,updated_at DESC) WHERE resolved_at IS NULL;
```
