# 从已清洗作品到分集定稿

一次选题锁定作品身份、发行版本和集数范围。以《火影忍者》第 5 集为例，正式章节需要解释卡卡西为何改变结论，并让读者从「分享午饭」回到有依据的原段。[业务流程图](diagrams/business.svg) · [配置示例](../data/episode-plans/naruto-tv-2002.json)

| 阶段 | 谁执行、写到哪里 | 推进条件与失败信号 |
| --- | --- | --- |
| 目录清洗 | Go 将上游记录归并到 PostgreSQL canonical 目录 | 可靠版本、来源标识与年份可核对。普通作品可停在这一阶段 |
| 选题登记 | 数据服务扫描挂载的 JSON，登记 `episode_plans`、`research_topics` 和美术任务设定 | 分集配置绑定同一 TV 版的 provider ID、集号、slug、来源、人物与场景。配置错误见 sync 日志 |
| 联网取证 | Pi 工具读取本集官方资料和独立分集资料；Go 保存 `research_runs.documents` 与 `research_events` | 标题、集号、快照摘要、可定位句子须匹配。失败保留 run、阶段和原因 |
| 写作与校对 | Pi 按顺序组织动机、转折和因果。Go 从快照解析引用，将段落与出处存入 claims | 只有通过结构与引用检查才进入 ready；工作台可查看来源索引 |
| 出图与验图 | Go 派发候选，Pi 核对参考图摘要，生成原图与手机裁切，调用视觉模型。Go 更新 `media_candidates` 和 `media_steps` | 配置式流程每集三张场景候选，跨集复用肖像。缺陷可触发二次复核、重裁或重绘。终止原因与各轮文件留在工作台 |
| 范围验收 | Go 将五维证据与缺项写入 `scope_acceptances`，以 `scope_heads` 指向最新检查和通过记录 | 有缺项时显示具体维度。配置式选题可将正文缺项退回提升 policy，保留旧稿和退回记录 |
| 对读者发布 | 冻结正文、章段锚点、插图及摘要；Gin 从公开视图返回连续通过的范围 | 后集先通过时等待前置集。H5 的已完成范围可从验收记录与返回链接复查 |

## 五维如何落到一集

| 维度 | 检查什么 |
| --- | --- |
| 人物 | 配置中指定人物能在对应、有来源的正文段落找到，角色页可以列出出场集 |
| 剧情 | 段落覆盖动机、转折和因果，每项引用能定位到同集快照 |
| 世界观 | 该集依赖的设定词出现在选定的有据段落，例如火影、铃铛或同伴 |
| 时间线 | 各剧情节点依次命中分集资料中的事件句子 |
| 图片 | 所需肖像有验图记录和文件；场景候选结束比选后，检查入选原图、裁切、尺寸、摘要及通过回执 |

这些自动门槛衡量当前配置的范围。角色名、设定词和句子定位包含字面匹配条件，来源改版或译名改变可能造成退回。读者页展示自然剧情；证据、各轮和缺项留在工作台。[范围检查](../apps/api/internal/service/knowledge/episode_plan.go) · [图片与定稿凭证](../apps/api/internal/service/knowledge/acceptance.go)

## 云端自动补集

按作品版本登记自动制作范围。广州优先选择处于盘点缺口、有已验证配置、且预算仍有余量的集。登记一集与开始付费制作各有自己的时间。采集、写作、出图分别使用共享库中的租约、研究运行和候选编号恢复。入选图、已发布版本与前文章段锚点保留。工作台「自动补集」展示准入与历次采集失败，「制作消耗」与范围验收展示模型回执和逐维缺项。[制作配置与预算](../data/production-plans/README.md) · [两端运行手册](../deploy/first-phase/README.md)

## 扩展与回归

已有 Naruto 适配器增加一集，只需向清单追加分集，并在需要时补人物参考。数据服务约每 45 秒读取配置；相同清单跳过，已登记项有修改保护。新的上游页面结构需要实现取证适配并验证实际文档格式。《星际牛仔》的历史双集及第 3 集仍有专用取证和验收逻辑。回归时要覆盖配置式单集及历史范围。[配置字段](../data/episode-plans/README.md) · [取证适配](../apps/agent/src/episode-plan.ts) · [历史范围](../apps/api/internal/service/knowledge/episode_three.go) · [追加配置测试](../apps/api/internal/service/knowledge/episode_plan_test.go)

## 已发布章节的编辑流程

1. 在工作台选章节并输入修改意见。Gin 记录当时的公开章节、场景、版本与任务提交人。
2. 数据服务领取任务。原创取证读取对应章节的创作定稿与场景设定。《火影忍者》第 1 集按分集配置读取官网与分集资料，检查集号、标题和原文指纹。网络暂不可用时可使用该集已有核验快照，来源标注取证方式。
3. Pi Durable 按意见写出逐字段修订及引文。Go 检查字段键、文本和逐字引用，Pi 另起一次校对，对照事实、因果与修改意图。失败原因进入执行记录；每轮最多三次尝试，耗尽后等候新的返工意见。
4. 审稿人在同一任务查看差异、出处及 H5 手机预览。退回会建立新轮次；批准仅对正在审核的轮次与尝试生效。若公开底稿已变化，任务显示冲突，可从最新定稿重新提意见。
5. Gin 在一个 PostgreSQL 事务中发布章节及场景文字、写审核记录并推进发布指针。阅读页继续使用原章节与场景链接、段落键和插画。历史快照与各次生成结果可在任务记录中追溯。

编辑人物介绍与世界观时，工作台以该章为取证范围，提供实际出场人物及作品页世界观字段。运营可在一句话中要求改一处或多处。审稿人可切换私有预览中的人物页与作品页，逐项对照引文，再整项批准。作品级发布指针与章节级发布指针分别校验底稿版本。再次修改其中一段会保留此前已通过的其他段落。原创作品允许首次补写世界观，获批后显示在作品页。[人物与世界观投影](../database/migrations/legacy/034.sql)
