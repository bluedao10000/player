# 一部作品怎样成为可公开阅读的知识库

设计基线为 2026-11-18，main 工作树（基于 0934920）。[产品架构](产品架构.md) · [可点击的构建流程图](architecture.html) · [两个样板的数据实例](作品世界样板/知识库清洗/流程说明.html)

## 先确定“哪部作品、哪个范围、哪个版本”

作品 UUID 标识一个具体改编版本。《星际牛仔》1998 TV 版的验收不能用于剧场版。一次选题锁定作品、来源快照、范围、剧透边界和预算。范围可以是前两集、一季、全作，也可以是「潮汐邮局」一组具名原创短篇。短篇合集用章节键集合表示，续写不会改变旧集合。

知识成熟度回答“现在已经能用哪些知识”。数据服务在 PostgreSQL 保存事实与验收记录，Gin 读取。工作台将成熟度、原作发行状态、公开版本并排显示，并另外展示当前任务和更新差距。

| 成熟度 | 最低依据 | 能做什么 |
| --- | --- | --- |
| 基础档案 | 清洗归并成功，有稳定作品身份和来源版本 | 搜索作品、查看别名、发行信息和出处。普通作品默认停在这里 |
| 已有关联知识 | 同一版本内至少有一条带证据的角色出场 → 章节 → 场景 → 正文段落路径 | 从角色找到出场章节，从场景回读原文。可以作为样板预览 |
| 知识已验收 | 已冻结范围内五维所有必需项均通过，结论绑定知识版本、输入证据与规则版本 | 有资格正式发布这个范围。候选验收与切换公开指针是两个动作 |

已验收要附范围。连载“已跟上至 N 集”要求截至核实日，已播前 N 集连续且全部验收；完结“全作已完成”要求整个具体版本已验收。未取得可靠的已播范围时展示“最新发行范围未知”。上游 13 集、已验收 12 集、正式公开 12 集，表示待补第 13 集。缺失中间集时列出缺集，不用最大集号表示连续覆盖。旧版的通过结论保留在旧版上。

## 从上游到读者的完整流程

| 步骤与责任方 | 输入 → 产出 | 判断与异常 |
| --- | --- | --- |
| 1. 数据服务定时检查（已有） | AOD Release 元数据、Bangumi 包版本 → 同步运行记录 | 版本未变记录跳过。下载失败保留旧库 |
| 2. 暂存与清洗（已有） | 完整下载、校验和 → 校验 JSONL 元数据及逐行记录／解析包 → 归一化批次 | 校验通过才合并，记录读取、变动和失败数 |
| 3. 匹配与建档（已有） | 来源记录、外部 ID、版本信息 → 规范作品、别名、发行、映射、来源版本 | 有歧义留候选，可调用已有 AI 判同。事务成功后普通作品留在基础档案 |
| 4. 决定投入（规划） | 运营策略选作品和范围 → 具名选题、必需项、上限及优先级 | 未选中继续定时同步。选中后各工序自动执行 |
| 5. 研究取证（规划，已有两部专用导入样板） | 数据服务委托 Pi Durable，结合清洗事实与联网核实 → 带来源、定位、获取时间和快照的事实 | 原创以自有稿件为准。外部作品优先官方和可定位资料。记录冲突、未知及站内解读，避免跨版本补错 |
| 6. 建立叙事关系（样板已有，通用生成规划） | 事实、分集材料、范围 → 人物动机与变化、主线因果、章节与段落、场景、设定和事件先后 | 每个出场、关键转折均可追溯。先有一条可回跳的证据链即可显示已有关联知识 |
| 7. 准备图片（CLI 试稿已有，自动流程规划） | 按作品主视觉、人物、场景及 H5 用途列图位 → 素材或 Pi 生成候选、派生裁切和检测记录 | 校验来源及使用依据、人物一致性、剧情和手机裁切。视觉疑点才交有视觉能力的 Jev／模型。先重裁、再重生成；授权缺证暂停该图位 |
| 8. 自动验收（规划） | 同一候选版本的五维结果 → 带范围与证据的验收记录 | 缺一必需项即列出阻塞项。取证不足待补证，内容不达标局部返工，超时按任务重试，超预算暂停；不需要人工审核 |
| 9. 正式发布（样板事务指针已有，正式验收联动规划） | 已验收版本、图位清单及稳定链接 → 原子切换公开版本 | 发布前重验输入版本和所有回跳锚点。Gin 只返回公开投影，H5 SSR 显示可读范围。可回退上一有效版本 |
| 10. 持续维护（上游同步已有，知识增量规划） | 新集、来源修正、图片使用权变化 → 受影响条目的新候选及复验任务 | 旧版可持续阅读；已撤权素材立即停用或替换。工作台分别追踪上游、已验收和已公开的范围 |

## 五个维度的验收凭证

| 维度 | 范围内必须能回答的问题 | 证据与缺口举例 |
| --- | --- | --- |
| 人物 | 谁想得到什么，哪次选择改变了关系？ | 核心人物清单、出场与变化对应章节。仅有人名时列为缺人物动机 |
| 剧情 | 事件为什么发生，转折带来什么后果？ | 主线／单元线与章节、关键段落可双向定位。两集导读不代表整季剧情完整 |
| 世界观 | 哪个设定影响了人物的行动？ | 规则、地点或组织与具体场景关联。只有地名时列为缺设定说明 |
| 时间线 | 故事内事件怎样排序，哪些是回忆或并行？ | 事件与来源、相对先后关系。播出顺序单列。次序未知可注明，涉及关键因果则阻塞 |
| 图片 | 每个必需图位能否用于实际手机页面？ | 素材来源或生成记录、使用依据、原图、裁切样张、校验结论。一个图位三张候选仍只算一个图位 |

工作台按维度展示已知内容、目标、验收结果和具体缺口。目标未定义时保留未知。人物数量、图片引用和质量验收分栏；可选图位不足不阻塞必需项。

## 数据与服务契约

- PostgreSQL 保存来源批次、规范作品、不可变知识版本、证据及公开版本指针。现有角色、章节、故事线、场景、出场关系、正文段落和设定构成两条阅读路径。后续增加选题范围、事实与出处、事件关系、图位与资产版本、逐项验收和任务记录。
- 腾讯云数据服务拥有调度、合并、预算、返工、验收和发布写入。按作品、范围、输入摘要与规则版本去重；任务带租约、尝试次数和错误原因。重跑复用有效结果，同作品切换版本采用事务和版本条件。原始资料与草稿对读者不可见。
- Pi Durable 执行联网研究、生成、视觉工具与断点恢复，返回任务 ID、结构化结果和依据。阿里云 Gin 读取 PostgreSQL 提供作品世界、出场、场景回跳及工作台状态。H5 和剧情 Agent 经 API 使用带版本的业务知识。
- 工作台展示最近运行、各维度库存、阻塞原因、版本与范围。运营配置选题和预算。读者只看到公开作品和可阅读范围，私人剧情与公开事实隔离。

## 实施与验收顺序

1. 第一阶段已接入只读作品状态 API 和工作台。以现有数据推导基础档案、关联路径及五维库存。验证两部样板、普通条目、空值和服务不可用。样板不自动授予正式验收。
2. 第二阶段接入《星际牛仔》1998 TV 前两集的固定选题。数据服务委托 Pi Durable 实时取证，按集串联十个关键事件并逐段引用来源。工作台可查看过程和失败原因，H5 提供分集预览。通用选题配置和独立时间线仍属后续能力。[本地验收说明](knowledge-base.md)
3. 第三阶段已接入阿澪固定参考立绘和三场景九个候选位。Pi 执行参考图生成、手机裁切与视觉检查，数据服务控制重裁、重绘及预算终止。工作台展示当前和历史构图。外部作品的素材权利核验和正式图片发布仍属后续阶段。
4. 联调五维验收、正式发布及增量重验。验证缺一项不发布、新集不影响上版和撤权能停用图片。以上阶段分别验收。

### 第四阶段本地验收

数据服务每分钟检查《星际牛仔》1998 TV 第 1–2 集，也可运行 `docker compose exec -T sync knowledge-sync -accept-scope`。每次用当前知识版本、取证批次、规则和文件凭证核对六位人物、两集剧情、两条影响行动的设定、每集五个有序事件，以及十个必需图位（主视觉、六张肖像、三张场景图）。两集各自维护故事内顺序。导读正文与已核实的来源快照绑定，修改样板导读后需要更新验收依据。

三个场景从各自通过验图的候选中选一张，核对原图指纹及对应轮次手机样张。依次优先较少重绘、无需重裁、初检无异议，同级按候选编号。五维全部通过后，数据服务在同一事务保存验收记录、定稿正文和入选图片引用，切换该范围的公开指针。重复运行复用相同记录。缺项会列在工作台，当前未通过的范围回到样板预览。撤回入选候选后公开接口立即停止提供该范围的定稿，下一轮可以改选其他合格候选。第 3–26 集不参与本期统计。此发布口径用于本地 H5 导读验收。

### 第 3 集增量发布

《Honky Tonk Women》有单独的第 3 集选题和发布记录。数据服务调度 Pi Durable 抓取官方简介与分集指南，核对快照及四组事件出处。取证完成后同一事务排入三个赌场场景候选和菲、戈登的肖像任务。媒体工作器负责生成、自动验图和返工。第 3 集五维全部通过且前两集仍可读时，H5 合并展示连续范围 1–3，旧章节与旧图继续从原定稿读取。增量缺项、上一次未通过的记录、研究批次及图片任务在本地工作台可查。[范围验收](http://127.0.0.1:4310/workbench#scope-acceptance) · [第 3 集](http://127.0.0.1:4310/work/cowboy-bebop-tv/chapter/honky-tonk-women)
