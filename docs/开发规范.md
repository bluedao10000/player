## 变更边界

Go 子项目各自维护 go.mod，使用 gofmt、Viper 和 Zap。GORM 与 pgx 共用 PostgreSQL 连接池。迁移使用独立版本号和 GORM Migrator，登记在 [database/migrations](../database/migrations/migrate.go)。建库入口统一为 database/migrations/init.sql，历史版本编号用于识别已有测试库；普通表使用迁移专属结构声明，涉及 PostgreSQL 视图、函数与回填时保留可复核的 SQL。数据库初始化和版本写入共用事务与 advisory lock。修改共享响应要兼容既有客户端和已存数据，尤其是双集范围、独立分集、已发布 slug 和段落锚点。H5 路由文件驱动生成 `routeTree.gen.ts`。公开正文由浏览器 loader 读取 Gin，交互状态留在对应组件。[迁移入口](../apps/api/internal/repository/database/store.go) · [共享类型](../packages/shared/knowledge.ts)

新增 Go 查询时，将完整语句放到 `apps/api/internal/repository/queries/<领域>/<用例>.queries`，用 -- name: 标记语句，在同领域的 Go 文件用 `//go:embed` 声明查询名。调用处负责传参、开事务、处理结果。数据值使用 PostgreSQL 位置参数；测试中动态创建的 schema 名通过 `pgx.Identifier.Sanitize()` 引用。测试专用语句归入 `apps/api/internal/testsupport/fixtures`，跟随测试编译。根目录的 `npm run check` 会检查 API、sync 和数据库模块中的 Go 字符串。[目录查询实例](../apps/api/internal/repository/queries/catalog/worlds.go) · [内联 SQL 回归检查](../apps/api/internal/repository/database/sql_boundary_test.go)

数据服务拥有业务幂等和发布决定。扩展 Agent 步骤时说明输入、允许的来源、输出、重试标识、终止条件和可追溯记录。将输出按不可信输入核验后再入库；观察模型调用的成功与否不能替代发布凭证。给已发布版本追加新范围时保留旧投影和回跳。[取证校验](../apps/api/internal/service/knowledge/research.go) · [媒体回执](../apps/api/internal/service/knowledge/media.go)

## 可执行反馈

在仓库根目录运行。常规检查无需访问计费模型。未提供 `KNOWLEDGE_TEST_DATABASE_URL` 时，部分 PostgreSQL 集成测试会跳过。下面第二条复用本机连接，在专用临时 schema 中建表并清理，需要建 schema 权限。

```sh
npm run check
node_modules/.bin/dotenv -e .env -- sh -c 'export KNOWLEDGE_TEST_DATABASE_URL="$DATABASE_URL"; go -C apps/api test ./... -count=1'
python3 -m json.tool apps/sync/episode-plan.example.json >/dev/null
docker compose config --quiet
python3 docs/check.py
git diff --check
```

`npm run check` 包含[界面文案检查](界面文案规范.md#工程约定)、Web 生产构建、workspace TypeScript 检查与 Web/Agent 单元测试、三个 Go 模块的 vet 以及 API、sync 测试。
