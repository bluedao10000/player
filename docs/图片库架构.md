# 图片库与模型出口｜目标设计

截至 2026-11-21，当前发布链路将入选图片随分集定稿从硅谷投递到阿里云。H5 通过既有场景和肖像路由供图。以下是下一阶段的建设方案。读者访问域名、作品和段落链接延续现有约定。[当前接收器](../apps/sync/cmd/reader-release) · [H5 路由](../apps/web/src/routes) · [目标技术图](diagrams/media-platform.svg) · [目标部署图](diagrams/target-deployment.svg)

首期《火影忍者》的 11 张图已在广州灰度供图。上传以受控导入实现，R2、通用资产管理接口和 AI 扩展仍为目标设计。[灰度运行说明](../deploy/image-pilot/README.md)

## 一张场景图如何到达读者

1. 广州数据服务领取分集任务，登记预算和候选资产 ID。广州 Pi Durable 执行生成、编辑和视觉评估。国内模型走配置的本地出口，需访问 OpenAI 等境外模型时，经 Mesh 调用硅谷模型网关。网关仅代理允许的模型和操作，返回供应商请求 ID 与用量；广州按调用回执去重记账。
2. 上传端将原始字节流交给广州 Axum 服务。服务限制体积、解码像素与并发，探测实际格式，计算 SHA-256，写临时文件后原子安装，再登记资产版本。上传重试复用幂等键。中断产生的无引用文件由对账任务回收。
3. libvips 按预设生成阅读大图、手机裁切和肖像缩略图。配方记录焦点、尺寸、质量、编码器及版本。原图可下载；展示图支持压缩、裁剪、缩放以及 WebP、AVIF，兼容端保留原有格式。用实际运行镜像做编解码样片测试。优先为入选图预生成，限制按需转换的规格与并发。
4. Gin 发布事务检查选图、衍生文件和五维验收，再写入公开引用。H5 或 iOS 请求原图片地址，阿里云网关按固定路由经 Mesh 访问广州图片服务。已发布的版本化图允许 CDN 长缓存，替换选图生成新版本。原链接通过别名找到既有版本。
5. 工作台查看文件大小、来源、处理配方、发布引用和失败原因。外部 AI 超时只影响对应异步任务，已发布图片继续从存储或缓存读取。

## 服务与数据归属

| 对象 | 权威位置与契约 |
| --- | --- |
| 原图、衍生图 | 广州专用持久卷。Rust 的存储接口提供 put/get/head/delete，物理对象键按摘要分片。衍生键包含源摘要、规范化配方和编码版本。用相同输入并发转换时只安装一份结果。 |
| 资产、目录、元数据 | PostgreSQL 保存资产 ID、逻辑目录与父目录、名称、来源与使用授权、作品/角色/场景关联、MIME、宽高、大小、摘要、版本、可见性和物理位置。移动目录只改元数据。Gin 管理发布关系，图片服务管理文件和衍生记录。 |
| 管理接口 | 内网上传、分页列目录、搜索元数据、移动/改名、下载原图、删除。删除先撤销可见性并检查发布引用；已定稿图片需显式撤稿或替换。无引用版本过保留期后异步清理字节，记录审计。 |
| 私有访问与缓存 | Gin 校验读者或运营身份后签发短期 URL，绑定路径、版本、变体及过期时间。图片服务验签。预览与候选图使用 private/no-store 并绕过共享缓存。公开 CDN 键包含版本和格式；旧别名短缓存，撤稿清边缘缓存并禁用源站读取。 |
| AI 派生信息 | 描述、标签、OCR、内容识别、质量分析返回带模型版本的结构化结果；生成、编辑、去背景、修复返回新资产版本，保留父版本。Go 调度、Pi 执行外部 API，记录请求、耗时、token 或按图用量、返工及费用。外部供应商只取得该任务所需图片。 |
| 灾备 | 现有 K3s 任务备份 PostgreSQL。新增图片卷须按清单异机增量备份原图、定稿图及版本元数据；恢复时以同一发布清单逐对象验摘要，抽查 H5 与 iOS 旧地址。可再生缩略图保留配方即可重建。 |

ImgForge 提供 Rust 图片代理与变换的参考，仓库标注 GPL-3.0。采用 Rust、Axum、libvips 的组合；资产目录、业务鉴权、定稿引用和 AI 任务沿用本项目的服务边界。引入上游代码前另行核对依赖及许可。[ImgForge 仓库](https://github.com/ImgForger/imgforge)

## R2 切换与回退

先用本地卷实现存储接口。容量、磁盘增长率、出网带宽、缓存命中率与图片读取 P95 作为迁移决策依据。第二阶段增加 S3 兼容适配器，按实际需要验证 PUT、HEAD、GET、Range 和 DELETE。[R2 的 S3 API 兼容表](https://developers.cloudflare.com/r2/api/s3/api/)

迁移期间以广州卷为主写，事务内登记复制任务。后台按清单回填历史对象并持续追平新增版本及删除标记；逐项核对字节数和应用层 SHA-256。已校验对象才可灰度从 R2 读取，缺失时回源广州并记录。切主写前核对积压为零、旧 URL、缓存与私有图鉴权。观察期保留广州副本并反向复制新增对象；回退前核对新增对象完整，按资产位置切回。读者 URL 全程使用本站域名。
