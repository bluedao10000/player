# 潮汐邮局 · 首轮 UI 评审

## 审计与设计决策

| 观察 | 设计决策 | 实现范围 |
| --- | --- | --- |
| 首页用纸张、邮戳和三栏卡片表达邮局主题，但翻到角色页仍是同一套容器。 | 让读者先看见阿澪值夜班的港口。人物横向浏览，故事用书目预览，剧情用场景图，地点链接到实际发生在那里的故事。 | 发现页、精选切换、港口人物、继续阅读、地点索引 |
| 阿澪只有一张日景插画，人物关系藏在故事里。 | 增加同一角色的夜间主视觉。船长与守塔人直接关联各自出场的故事。 | 角色主页、两个人物关系锚点 |
| 阅读页的大外框和操作行占据注意力；移动端的两行顶栏挤占首屏。 | 封面交代场景，正文限制到 690px，读完才给剧情入口；手机固定四入口底栏。 | 故事页及共用导航 |
| 剧情试玩已有开场、两个行动和结尾；当前数据仅有一个完整角色主页。 | 复用已有行动与收藏逻辑。两个配角使用人物关系锚点。 | 前端展示适配，本轮未增加业务实体 |

## 设计系统

- **色彩与材质**　深靛底色、暖白正文与淡紫主行动。插画承担主要色彩；半透明层集中在导航和场景过渡区域。
- **排版**　界面采用系统无衬线，封面标题采用中文衬线。公开正文 17–20px，行高 2.05。章节标题、简介和正文按语义分别渲染。
- **尺寸与动作**　间距、字号、四档圆角、材质、模糊、描边阴影、动效与层级集中在 [设计令牌](../../apps/web/src/features/post/tokens.css)。移动导航预留底部安全区，热区至少 44px；减少动态效果偏好下关闭入场和缩放。
- **组件**　按钮、图标按钮、头像、标签和章节标题是基础元素。角色主视觉、人物链接、故事预览、场景预览和地点预览各自表达一种内容。阅读进度仅保存在本地。剧情共用对白、叙述与行动选择组件。详见 [基础组件](../../apps/web/src/features/post/design.tsx) 和 [核心页面](../../apps/web/src/features/post/editorial.tsx)。

## 验收结果

在 Chromium 中按 375、390、430、1440px 检查首页、角色、故事列表、书架、四篇故事和四个对应的剧情入口。四组均通过页面宽度检测、单一 H1、内容导航、精选切换、收藏、继续阅读、类型筛选、进入剧情并刷新恢复的检查。三个手机尺寸的固定底栏均为四项，点按区域至少 44 × 44px。本次为浏览器视口验证，iOS 真机安全区和 Capacitor 原生容器仍需设备验证。

三个核心页面的响应 HTML 包含标题、描述和可见正文；禁用 JS 后可从首页经角色链接读完《末班渡船》。无效故事与剧情 slug 返回 404。原型此前尚无 canonical、JSON-LD 和 sitemap，仍属公开发布阶段的 SEO 工作。构建与类型检查通过，命令为 `npm run check`。

建议下一轮单独设计 Roleplay，让角色对白、场景变化和下一步行动组成连续的视觉小说体验。首轮评审重点是从公开阅读进入剧情的时机。
