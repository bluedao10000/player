# 模型接入、用量与计费

知识库写作、出图、验图和判同按回执统计平台成本。读者可购买会员，供应商成本按日核对。

## 配置四条调用路径

每条路径分别设置 `*_BASE_URL`、`*_MODEL`、`*_API_KEY` 和 `*_ACCOUNT`。ACCOUNT 填稳定的供应商计费账户别名，例如 `studio-openai-prod`。共用计费账户的路径使用相同别名，轮换同一账户的 Key 时保留别名。不同账户应使用不同别名，方便对账。配置位置见[环境模板](../deploy/.env-example)和[容器映射](../deploy/docker-compose.yml)。

| 用途 / purpose | 配置前缀 | 实际执行 |
| --- | --- | --- |
| 分集取证与知识库写作 / content | CONTENT_AI | 数据服务调度 Pi。OpenAI Responses 接口选 `CONTENT_AI_PROTOCOL=responses`。DeepSeek 等兼容服务选 `chat-completions`，填写该服务的 URL、模型名和 Key。流式客户端请求供应商返回 usage |
| 参考图、场景图、肖像与返工 / image | MEDIA_AI | Pi 媒体步骤使用兼容 OpenAI Images 的生成或编辑接口。生产调度开关为 `MEDIA_WORKER_ENABLED` |
| 图片初审与复审 / vision | VISION_AI | 使用支持图片输入的 Responses 接口。初审使用 `VISION_AI_MODEL`，复审使用同一账号下的 `VISION_AI_SECOND_MODEL`，两个步骤分别计量 |
| 作品判同 / match | TYPESAFE 或 MATCH_AI | Gin 管理接口按既有路径执行。Jev 选 `MATCH_AI_PROVIDER=typesafe`，使用 `TYPESAFE_*` 调用 `/systemone`。也可选 `openai` 用 `MATCH_AI_*` 配置 Chat Completions |

可在各服务分别填写同一把有相应权限的 Key，也可以独立轮换。内容和视觉在未指定自定义地址时兼容历史研究 Key；显式指定地址后要给对应路径设置 Key。Jev 的 Key 只给执行判同的 API 服务。本地开发用根目录 Compose 应用配置；部署环境使用 deploy/docker-compose.yml 并显式设置唯一 OPS_NODE_NAME 后再重建服务。H5 无需模型凭据。

## Pi 接入 Magpie

Pi Durable 持有分集会话、取证工具和检查点。Pi AI 的内容 provider 可以将同一个工作流送往直连供应商或 Magpie。数据服务继续在 PostgreSQL 记录实际请求和验收结果。Magpie 提供 OpenAI Chat Completions 和 Responses 兼容入口，支持流式返回和工具调用。本项目的网关路径使用 Chat Completions，显式请求流末 usage。[Magpie 上游说明](https://github.com/yetone/magpie#how-it-fits-together) · [Pi 接入实现](../apps/agent/src/content-provider.ts)

在运行 Agent 的环境中选择模式。本机 Docker Desktop 可沿宿主机访问 Magpie，默认网关端口为 3425。生产可设置独立 HTTPS 网关地址和该客户端专用的 gateway key。供应商 Key 留在原有直连配置或 Magpie 上游配置里。

```dotenv
CONTENT_AI_MODE=magpie
MAGPIE_CONTENT_MODEL=volcengine/kimi-k3.1-pro
MEDIA_AI_MODE=direct
ORIGINAL_MEDIA_AI_MODE=magpie
MAGPIE_ORIGINAL_IMAGE_MODEL=volcengine/doubao-seedream-5-0-pro
```

- `MAGPIE_CONTENT_MODEL` 是网关路由，可使用供应商模型或 Magpie 路由组。先从 Agent 所在网络访问 `/v1/models`，再用具体路由验证工具调用和带 usage 的流。目录可能晚于实际可调用版本。
- `MAGPIE_BASE_URL` 在宿主机默认使用 `http://127.0.0.1:3425/v1`，Compose 默认使用 `http://host.docker.internal:3425/v1`。跨机使用 HTTPS，并设置 `MAGPIE_API_KEY`。网关可按客户端密钥设置可用模型和限额。[Magpie 网关密钥](https://github.com/yetone/magpie/blob/main/docs/reference.md)
- `MAGPIE_ACCOUNT` 是总账的网关账户别名，默认 `magpie`。要区分多个团队或套餐时分别设置。切回 `CONTENT_AI_MODE=direct` 即恢复已有内容模型配置。修改后重建 Agent 容器环境，已完成的集数继续复用定稿。知识库出图通过 `MEDIA_AI_MODE` 独立切换。Pi 将参考图以 multipart 提交给 Magpie 的 `/v1/images/edits`，显式传入 `MAGPIE_IMAGE_MODEL`。Nano Banana 2 的路由为 `google/gemini-3.1-flash-image`，Google 凭据由网关持有。验图和 Jev继续使用各自的直连接口。Magpie 的图片目录可用 `magpie tools generate_image` 查询。
- 数据服务的原创潮汐邮局图片任务使用 `ORIGINAL_MEDIA_AI_MODE` 和 `MAGPIE_ORIGINAL_IMAGE_MODEL`。未设置原创模式时，沿用通用图片配置。现有动画作品的参考图任务使用 `MEDIA_AI_MODE`，本机设为 `direct` 并使用现有 OpenAI 凭据。两路实际使用的模型与账户都会写入回执。
- 网关提供路由和配额管理；实际 token 由上游和上下文决定。不同模型的 token、图片张数、套餐额度和人民币各自统计。网关返回的模型名可能只是路由名，因此使用固定路由验证全作，在有上游账单前不要推算实际货币成本。缺失 usage 的请求在报告中单列。Magpie Images 可在 Google 未提供计数时填入三个零；对已返回图片的这类回执，账本保留张数并标记 token 未报告。

按作品核对分集、共享肖像和全作用量。查询覆盖重试与返工，通过回执键去重。在线生产的账本与本地验收库应分别核算。

打开内部数据工作台，在「作品制作 · 用量与耗时」展开对应分集。

若 Magpie 对 Nano Banana 2 返回 403，在 Magpie 中检查 Google 提供商对应项目是否已启用 Generative Language API。工作台保留失败回执；恢复权限后，执行以下命令恢复这部作品因供应商报错而失败的出图步骤。调度器需启用 `MEDIA_WORKER_ENABLED=true`。每次恢复使用新的尝试号，已定稿图片、参考图和验图结果均可复用。

```sh
docker compose exec -T sync knowledge-sync -resume-image-work takopi-ona-2025
```

## 在数据工作台核对作品制作

数据工作台的「作品制作 · 用量与耗时」从 Gin 管理接口 `GET /api/v1/admin/knowledge/production-usage` 读取配置式选题的聚合回执。启用内部工作台时给 H5 服务端配置与 Gin 一致的 `KNOWLEDGE_ADMIN_TOKEN`。表内模型耗时是请求耗时之和，端到端是首次调度到验收发布的经过时间。失败和返工保留在回执中，未报告计量的请求单列。「范围验收」同时保留当前缺项和最近一次未通过的检查。

## 一次模型调用怎样记账

假设第一次出图后，初审发现裁切问题并启动视觉复核。这会分别留下出图、初审和复审三次请求，关联媒体槽位、轮次、步骤和业务尝试号。若随后只用本地工具重新裁切，就没有新的模型用量；若重新出图，则增加一次图片请求。判同直接复用已保存结论时同理。供应商已返回用量后，即使 PNG 解码或结论校验失败，仍计入生产消耗。

1. Pi 在发送 HTTP 前把调用 UUID 和任务身份写入持久卷里的 SQLite 发件箱。收到 JSON 或流式回执后，追加结束事件。数据服务分批写 PostgreSQL，提交成功后才向 Agent 确认。进程重启或确认丢失均可重送。
2. Go 判同先独立登记请求，再访问供应商。最终回执使用独立上下文写入，即使治理事务回滚也能保留。回写暂时失败时保存至归档卷中的 `model-usage-outbox`，常驻数据服务回放。需手动回放归档回执时可执行 `knowledge usage-import --dir <回执目录>`。
3. 表 `model_calls` 保留每次 HTTP 尝试，包括重试。视图 `model_usage_receipts` 在相同端点与供应商账户内，优先使用供应商响应 ID，再使用请求 ID 关联重复回执。没有供应商 ID 时以本次调用 UUID 区分。图片请求携带的幂等键可辅助查账，单靠该键无法证明供应商只扣过一次费。
4. 同一回执只汇总一次。收到相互冲突的输入、输出、总数等记录时保留原始尝试，标为 `inconsistent`。崩溃可能发生在供应商已执行、客户端尚未收到回执的间隙，`started` 或 `unknown` 会保留以待核对。若供应商既不提供回执 ID 也不提供历史账单明细，系统无法保证跨请求识别所有重复扣费。

持久记录含账户别名、配置端点、请求与返回模型名、任务身份、HTTP 状态、时间和用量。用量字段只保留数值与数值分项，账本排除 Key、提示词、正文和图片内容。[账本迁移](../database/migrations/init.sql) · [Pi 采集](../apps/agent/src/model-api.ts) · [Go 持久化](../apps/api/internal/service/modelusage)

## 怎样读用量

| 回执状态 | 解释 |
| --- | --- |
| measured | 上游报告总量，或提供了可相加的输入和输出。明确返回的零保留为零 |
| partial | 只有部分 token 计数，已知分项保存在明细中 |
| unreported | 请求已结束，供应商没有提供可识别的 token 总量或输入输出分项 |
| unresolved | 没有完整的调用结果，实际消耗需要核对 |
| inconsistent | 同一回执的数字有冲突或与其分项合计不符，需要核对 |

汇总取去重后的 measured 记录。输入和输出或供应商细分项缺失时保留空值。缓存、推理、图像与文本 token 可能是输入或输出的子集，重复相加会高估消耗。图像同时保存返回张数、请求尺寸和指定画质。例如接口成功返回一张图却省略 usage，查询会显示一张图及未知 token。上线前的历史任务没有逐次回执，保留其既有业务记录。

管理员可用以下命令查询。运行前把管理 token 放在当前环境中，基础地址可由 `KNOWLEDGE_API_URL` 指定。

```sh
usage_url="${KNOWLEDGE_API_URL:-http://127.0.0.1:4321}/api/v1/admin/knowledge/model-usage"
curl -fsS -H "Authorization: Bearer ${KNOWLEDGE_ADMIN_TOKEN}" "$usage_url"
curl -fsS -H "Authorization: Bearer ${KNOWLEDGE_ADMIN_TOKEN}" \
  --get "$usage_url/calls" --data-urlencode "subject=research:${RESEARCH_RUN_ID}" --data-urlencode 'limit=20'
```

汇总默认最近 30 天，按用途、供应商端点、账户和实际模型分组。可用 RFC3339 的 `from`（含）与 `to`（不含）指定结算窗口。汇总按同一回执最早的请求时间归属，跨日重送只计入原窗口；调用明细按各次尝试的时间过滤。`duplicates` 为重复回执次数，`unmetered` 为未纳入 token 合计的唯一回执数，`unresolved` 统计状态未确定的实际尝试。明细用上一页最小 `seq` 作下一页的 `before`。回执明细可查看缓存、推理、图像等供应商实际返回的数值。[管理 API](../apps/api/internal/handler/knowledge/usage.go)

本地验收尚未启用管理账户时，可以直接用数据库只读查询观察计量。下面按用途列出去重回执数、缺失或冲突回执数，以及可核实的 token 合计。空账本返回零行。

```sh
docker compose exec -T postgres psql -U anime -d anime_knowledge -c "
  SELECT purpose, count(*) AS receipts,
         count(*) FILTER (WHERE meter_state <> 'measured') AS needs_review,
         sum(total_tokens) FILTER (WHERE meter_state = 'measured') AS tokens
  FROM model_usage_receipts WHERE receipt_rank = 1
  GROUP BY purpose ORDER BY purpose"
```

本机 Compose 的 Agent 仅在容器网络内提供回执读取与确认。备份应包括 PostgreSQL、Agent 状态卷和归档卷。双云拆分时，确保回执写入方所在机器的磁盘可由恢复任务读取，跨主机的内部接口使用服务身份认证和加密传输。[运维手册](运维手册.md)

## 会员购买

H5 从「我的」发起支付宝会员订单，签名通知到达后激活会员。iOS 用 StoreKit 购买同一读者账户的会员。两端共享会员期和积分。原约稿账户、订单及资金流水保留供历史核账。发布前应在原版本核对待支付充值、未履约订单和剩余余额，完成交付、退款或与渠道对账后停用旧 worker，并在商店下架旧充值商品。[会员与支付](读者账户/设计.md#微信登录与读者会员)

## 供应商成本费率

管理接口前缀为 `/api/v1/admin/knowledge/billing`。用 `POST /rates` 登记合同费率，`kind` 填 `cost`，按供应商端点、账户、实际模型、币种与生效时间选择版本。`image` 按张计价，`total_tokens` 或 `split_tokens` 按每百万 token 计价。金额以对应币种的微单位保存。用 `GET /rates` 查版本历史。

## 怎样核对每日账单

1. 将供应商账单按 **UTC 日期 × 端点 × 计费账户 × 模型 × 币种** 汇总。管理端 `POST /statements` 提交 `day`、`endpoint`、`provider_account`、`model`、`currency`、`amount_micros` 和原凭证 `reference`。账单修订使用新 reference，并以 `replaces` 指向本组上一条凭证。可重复导入同一行。
2. 查 `GET /reconciliation?day=YYYY-MM-DD&currency=CNY`。每组同时展示去重回执数、待核回执数、已知成本、供应商金额与销售净额。差额等于供应商金额减本地应付。
3. 差额或待核项可下钻 `GET /reconciliation/receipts`，使用同一日期和币种，可按 `provider_account`、`model` 过滤，以 `after` 传上一页最后一个 call_id。用 `GET /statements` 核查该日所有原始和修订凭证。

| 日账状态 | 含义 |
| --- | --- |
| matched | 已知本地成本与供应商同组金额一致 |
| difference | 两侧金额都有，存在差额 |
| pending | 成本费率、用量或归属还需补核 |
| local_only / supplier_only | 仅一侧有记录，需要补账或核对分组 |

毛利在已匹配且收入币种可比时给出，等于同组用户净收入减供应商金额，含平台制作成本。退款回溯至原服务日，因此历史毛利会反映后续退款。报表直接读取已导入的供应商日账及最新有效修订。支付宝渠道账单下载与原路退款、自动拉取各模型供应商账单、跨币种折算属于后续接入范围。

设置 `KNOWLEDGE_TEST_DATABASE_URL` 后执行 `go -C apps/api test ./internal/handler/knowledge -run TestSupplierCostReconciliation -count=1`，验证去重、账单修订、差额与缺失回执。[集成测试](../apps/api/internal/handler/knowledge/billing_test.go)
