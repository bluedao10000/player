# 模型接入、用量与计费

当前可以回答「为某一集写正文、画图、验图分别调用了什么模型，供应商回报了多少 token」。每次实际发送的模型请求都有一条 PostgreSQL 记录。当前任务的成本归属为平台内容生产。零售价、用户账户扣费和供应商账单对账属于下一阶段。

## 配置四条调用路径

每条路径分别设置 `*_BASE_URL`、`*_MODEL`、`*_API_KEY` 和 `*_ACCOUNT`。ACCOUNT 填稳定的供应商计费账户别名，例如 `studio-openai-prod`。共用计费账户的路径使用相同别名，轮换同一账户的 Key 时保留别名。不同账户应使用不同别名，方便对账。配置位置见[环境模板](../.env.example)和[容器映射](../compose.yaml)。

| 用途 / purpose | 配置前缀 | 实际执行 |
| --- | --- | --- |
| 分集取证与知识库写作 / content | CONTENT_AI | 数据服务调度 Pi。OpenAI Responses 接口选 `CONTENT_AI_PROTOCOL=responses`。DeepSeek 等兼容服务选 `chat-completions`，填写该服务的 URL、模型名和 Key。流式客户端请求供应商返回 usage |
| 参考图、场景图、肖像与返工 / image | MEDIA_AI | Pi 媒体步骤和独立预览 CLI 使用兼容 OpenAI Images 的生成或编辑接口。生产调度开关为 `MEDIA_WORKER_ENABLED` |
| 图片初审与复审 / vision | VISION_AI | 使用支持图片输入的 Responses 接口。初审使用 `VISION_AI_MODEL`，复审使用同一账号下的 `VISION_AI_SECOND_MODEL`，两个步骤分别计量 |
| 作品判同 / match | TYPESAFE 或 MATCH_AI | Gin 管理接口按既有路径执行。Jev 选 `MATCH_AI_PROVIDER=typesafe`，使用 `TYPESAFE_*` 调用 `/systemone`。也可选 `openai` 用 `MATCH_AI_*` 配置 Chat Completions |

可在各服务分别填写同一把有相应权限的 Key，也可以独立轮换。内容和视觉在未指定自定义地址时兼容历史研究 Key；显式指定地址后要给对应路径设置 Key。Jev 的 Key 只给执行判同的 API 服务。配置变更用 `docker compose up -d` 应用。H5 无需模型凭据。

## 一张候选图怎样记账

假设第一次出图后，初审发现裁切问题并启动视觉复核。这会分别留下出图、初审和复审三次请求，关联媒体槽位、轮次、步骤和业务尝试号。若随后只用本地工具重新裁切，就没有新的模型用量；若重新出图，则增加一次图片请求。判同直接复用已保存结论时同理。供应商已返回用量后，即使 PNG 解码或结论校验失败，仍计入生产消耗。

1. Pi 在发送 HTTP 前把调用 UUID 和任务身份写入持久卷里的 SQLite 发件箱。收到 JSON 或流式回执后，追加结束事件。数据服务分批写 PostgreSQL，提交成功后才向 Agent 确认。进程重启或确认丢失均可重送。
2. Go 判同先独立登记请求，再访问供应商。最终回执使用独立上下文写入，即使治理事务回滚也能保留。回写暂时失败时保存至归档卷中的 `model-usage-outbox`，常驻数据服务回放。独立预览命令离线时回执保存在系统用户缓存的 `tidepost/model-usage-outbox`，有数据库连接时可执行 `knowledge usage-import --dir <回执目录>`。
3. 表 `model_calls` 保留每次 HTTP 尝试，包括重试。视图 `model_usage_receipts` 在相同端点与供应商账户内，优先使用供应商响应 ID，再使用请求 ID 关联重复回执。没有供应商 ID 时以本次调用 UUID 区分。图片请求携带的幂等键可辅助查账，单靠该键无法证明供应商只扣过一次费。
4. 同一回执只汇总一次。收到相互冲突的输入、输出、总数等记录时保留原始尝试，标为 `inconsistent`。崩溃可能发生在供应商已执行、客户端尚未收到回执的间隙，`started` 或 `unknown` 会保留以待核对。若供应商既不提供回执 ID 也不提供历史账单明细，系统无法保证跨请求识别所有重复扣费。

持久记录含账户别名、配置端点、请求与返回模型名、任务身份、HTTP 状态、时间和用量。用量字段只保留数值与数值分项，账本排除 Key、提示词、正文和图片内容。[账本迁移](../apps/api/internal/knowledge/sql/029.sql) · [Pi 采集](../apps/agent/src/model-api.ts) · [Go 持久化](../apps/api/internal/modelusage)

## 怎样读用量

| 回执状态 | 解释 |
| --- | --- |
| measured | 上游报告总量，或提供了可相加的输入和输出。明确返回的零保留为零 |
| partial | 只有部分 token 计数，已知分项保存在明细中 |
| unreported | 请求已结束，供应商没有提供可识别的 token 总量或输入输出分项 |
| unresolved | 没有完整的调用结果，实际消耗需要核对 |
| inconsistent | 同一回执的数字有冲突或与其分项合计不符，需要核对 |

汇总取去重后的 measured 记录。输入和输出或供应商细分项缺失时保留空值。缓存、推理、图像与文本 token 可能是输入或输出的子集，重复相加会高估消耗。图像同时保存返回张数、请求尺寸和指定画质。例如接口成功返回一张图却省略 usage，查询会显示一张图及未知 token。上线前的历史任务没有逐次回执，保留其既有业务记录。

管理员可用以下命令查询。运行前把管理 token 放在当前环境中，基础地址可由 `KNOWLEDGE_API_URL` 指定。

```sh
usage_url="${KNOWLEDGE_API_URL:-http://127.0.0.1:4321}/api/v1/admin/knowledge/model-usage"
curl -fsS -H "Authorization: Bearer ${KNOWLEDGE_ADMIN_TOKEN}" "$usage_url"
curl -fsS -H "Authorization: Bearer ${KNOWLEDGE_ADMIN_TOKEN}" \
  --get "$usage_url/calls" --data-urlencode "subject=research:${RESEARCH_RUN_ID}" --data-urlencode 'limit=20'
```

汇总默认最近 30 天，按用途、供应商端点、账户和实际模型分组。可用 RFC3339 的 `from`（含）与 `to`（不含）指定结算窗口。汇总按同一回执最早的请求时间归属，跨日重送只计入原窗口；调用明细按各次尝试的时间过滤。`duplicates` 为重复回执次数，`unmetered` 为未纳入 token 合计的唯一回执数，`unresolved` 统计状态未确定的实际尝试。明细用上一页最小 `seq` 作下一页的 `before`。回执明细可查看缓存、推理、图像等供应商实际返回的数值。[管理 API](../apps/api/internal/knowledge/usage.go)

本地验收尚未启用管理账户时，可以直接用数据库只读查询观察计量。下面按用途列出去重回执数、缺失或冲突回执数，以及可核实的 token 合计。空账本返回零行。

```sh
docker compose exec -T postgres psql -U anime -d anime_knowledge -c "
  SELECT purpose, count(*) AS receipts,
         count(*) FILTER (WHERE meter_state <> 'measured') AS needs_review,
         sum(total_tokens) FILTER (WHERE meter_state = 'measured') AS tokens
  FROM model_usage_receipts WHERE receipt_rank = 1
  GROUP BY purpose ORDER BY purpose"
```

本机 Compose 的 Agent 仅在容器网络内提供回执读取与确认。备份应包括 PostgreSQL、Agent 状态卷和归档卷；独立 CLI 的离线缓存另行备份。双云拆分时，确保回执写入方所在机器的磁盘可由恢复任务读取，跨主机的内部接口使用服务身份认证和加密传输。[运维手册](运维手册.md)

## 未来怎样把用量变成收入

| 上线收费前的工作 | 结算约定 |
| --- | --- |
| 区分平台与付费用户 | 现有知识库取证、出图与验图归平台。开放付费互动时，在服务端受理请求时同时绑定付费账户、业务订单、授权额度，并将其传给所有子步骤。公开内容的每次浏览无需分摊一遍生产 token |
| 维护两套价格 | 供应商成本价与产品售价分别版本化。按模型快照、计量单位、币种和生效时间选择价格，账单固定费率版本。总 token 数适合观察产量，输入、缓存输入、输出或按张计价的模型可能有不同单价 |
| 生成费用明细 | 把可核对回执拆成互斥计价项，以高精度十进制或整数最小单位计算，按账单币种统一舍入。仅有总量而费率区分输入/输出时，等待分项或供应商明细。发生返工与重试时，供应商成本可有多笔，用户收费由该订单的产品承诺决定 |
| 防止重复扣款 | 为「付费订单＋业务动作＋价目项」建立唯一键，出账和账户流水在同一事务内提交。修正通过追加调整或退款流水完成，保留最初报价与原始回执 |
| 对账并看毛利 | 定期按供应商账户、模型、周期核对账单，分别列出已匹配、待核对及差额。按作品和订单归集生产成本，再与对应收入比较。用量未知或冲突的记录留在待核对队列，完成核对后再结算 |

当前管理 API 返回调用与用量，未来对账和定价可复用这些凭证。首次启用真实收费前，应以同一批真实回执和供应商账单验证费率、缓存折扣、舍入、重试与退款。
