# 本地启动、观察与恢复

本手册中的根目录 docker compose 命令用于本地开发环境；根目录入口在 OPS_NODE_NAME 缺失或留空时使用 local，无需 compose.local-env。部署新环境请使用 deploy/docker-compose.yml，显式填写每台节点唯一的 OPS_NODE_NAME。命令从仓库根目录执行。首次拉取源码可以重建程序、数据库结构与选题配置；既有取证结果、模型生成图和发布记录属于运行数据。要原样复现一套定稿，需要配套卷或备份。

## 启动

本地 H5 通过 `npm run dev:web` 启动。公开 H5 使用 [Nginx 网关](../deploy/gateway/README.md)。

1. 安装 Node 24.13 以上的 24.x、npm、Go 1.25+、Docker Compose。运行 `test -f .env || cp .env.example .env`，首次设置 `POSTGRES_PASSWORD`。已初始化卷的密码应与数据库角色一致。[模板](../deploy/.env-example)
2. 运行 `npm ci` 与 `docker compose up -d --build`。PostgreSQL 健康后 API 执行迁移，sync 常驻导入。空库需等对应 canonical 作品出现，分集清单下次扫描时会再次登记。
3. 单独启动 H5。默认配置运行 `npm run dev:web`；自定义端口或知识 API 时用 `node_modules/.bin/dotenv -e .env -- npm run dev:web`。打开 [首页](http://127.0.0.1:4310/)。

| 功能 | 服务端配置 |
| --- | --- |
| 目录下载 | 默认走公开来源；`KNOWLEDGE_GITHUB_TOKEN` 可提高 GitHub 配额 |
| Pi 联网取证与知识库写作 | `CONTENT_AI_*` 设置协议、端点、模型、Key 及账户；旧部署兼容研究 Key。四路配置与用量查询见[模型用量与计费](模型用量与计费.md) |
| 自动出图与视觉验图 | `MEDIA_WORKER_ENABLED=true` 启用图片调度。出图使用 `MEDIA_AI_*`，初审与复审使用 `VISION_AI_*`。启用后新任务会调用计费模型 |
| 判同治理 | `KNOWLEDGE_ADMIN_OPERATOR`、至少 32 字节的 `KNOWLEDGE_ADMIN_TOKEN`；按 provider 配置 `MATCH_AI_*` 或 `TYPESAFE_*`。密钥留在对应服务 |
| 分集配置 | Compose 将 私有目录 `${EPISODE_PLAN_DIR:-./.local/episode-plans}` 挂到 sync 的 `EPISODE_PLAN_DIR`。新增集数只需保存配置。环境变量变动后用 `docker compose up -d` 应用到容器 |

## 只读检查

```sh
docker compose ps
curl -fsS http://127.0.0.1:4310/healthz
curl -fsS http://127.0.0.1:4321/healthz
docker compose exec -T research-agent node -e "fetch('http://127.0.0.1:4312/healthz').then(r=>r.json()).then(console.log)"
docker compose logs --tail=80 sync research-agent
```

Gin 健康检查会 ping 数据库。Agent 健康只说明进程可响应。业务就绪要看来源是否成功导入、当前 policy 的研究是否 ready、候选是否终止、范围是否 published。[验收记录](架构实现核验.md)

| 现象 | 定位顺序 |
| --- | --- |
| H5 可打开但作品列表为空 | 看 H5 的 `KNOWLEDGE_API_URL`，然后看 Gin 健康、来源列表和 sync 日志。对照上次成功版本、错误信息和暂存量 |
| 新集没有开始 | 查 sync 日志中的清单解析、已登记项变动或 canonical 身份错误，再查 `research_runs`。真实新集要追加独立集号和稳定路由 |
| 取证失败或返回重写 | 查分集 run 的 stage、policy、attempt、events 与来源标题、定位句；确认 Agent 内模型配置。保留旧回执供比较 |
| 长期缺图 | 查 `media_candidates` 的 step、round、reason；核对图片调度开关、两类模型凭据、参考图指纹及媒体卷权限 |
| 五维验收通过但 H5 范围没推进 | 核对同版本的前置集、published 指针、撤回记录和可见视图；若素材 HTTP 404，再核对实际卷与内容地址 |
| 想重查某一来源 | `docker compose exec sync knowledge-sync -once -source bangumi-data` 会执行一次探测，版本不变会跳过；`-refresh` 可触发重新归并。常规排查先看 sync 日志 |

## 数据工作台后端联调

工作台按 [API 契约](api-contract.md) 调用 Gin 的 `/api/v1`。开发用根 Compose 的 API（默认 `127.0.0.1:4321`），工作台前端的同源代理指向该端口。令牌由受信任的工作台代理转发为 `Authorization: Bearer …`。联调可直接用 curl 带同一个令牌请求。设置 `KNOWLEDGE_ADMIN_TOKEN`（至少 32 字节）和 `KNOWLEDGE_ADMIN_OPERATOR`；凭据保存在代理服务端。代理应保持 SSE 无缓冲并允许至少 300 秒的读取超时。

根 Compose 在同一端口提供[本地 HTTP 契约](http://127.0.0.1:4321/docs/api-contract.md)，可直接读取 Markdown。开发前端可设置 `VITE_API_MODE=real` 和 `VITE_PROXY_TARGET=http://127.0.0.1:4321`。

工作台读取制作库。生产联调使用私网 Gin 实例，连接制作库和 `KNOWLEDGE_RESEARCH_URL` 指向的 TypeScript Agent。只校验模式需要先由迁移身份应用 066 和 067。运行身份需要读取工作台视图和业务事实、写入工作台事务表；来源同步身份也需要通过触发器写入收件箱。Agent 用既有内容模型配置和用量回执，模型未配置时查询和审批仍可使用。[路由](../apps/api/internal/handler/workbench/api.go) · [迁移](../database/migrations/066_workbench.sql) · [模型流](../apps/agent/src/workbench.ts)

- 作品覆盖率使用已发布集数除以有可靠总集数的同版作品集数。超范围集号、未知总集数及不适用的作品类型返回 `null`。画像统计当前发布版带依据的角色、章节与场景，时间线事件缺统一数据源时返回 `null`。费用使用去重的供应商回执和 USD 成本费率。
- 收件箱执行来源快照核对和知识计划审批。来源核对记录操作者和结论；计划获批时更新计划状态并留下执行回执。作品版本、定稿指针、自动制作和发布均沿用现有流程。
- 聚合卡片用 `GET /api/v1/artifacts/{type}/{ref}` 读取落盘快照。画像、概览、运行统计和趋势的响应约定见[联调补充](api-contract.md#11-工作台联调补充)。
- 请求 `GET /api/v1/runs/{id}/events` 读取 Agent 已落盘的进度和正文。调用取消端点或在浏览器中断开 SSE 后，`GET /api/v1/agent/runs/{id}` 可核对 `cancelled` 状态。

## 公网索引检查

每次变更公开路径或发布范围后，用正式域名核对 robots.txt 和 sitemap，再查看作品、章节、角色和场景页的原始 HTML。确认 canonical 使用正式域名且保留原路径，JSON-LD 可解析，场景链接仍能回到章节的 `#passage-*`。旧工作台和预览路径应返回 404，且不得出现在 sitemap 内。

```sh
curl -fsS https://www.codeiy.com/robots.txt | rg '^Sitemap:'
curl -fsS https://www.codeiy.com/sitemap.xml | rg -c '<loc>'
curl -fsS https://www.codeiy.com/work/apothecary-diaries-s3-2026 | rg -o 'rel="canonical"[^>]*|type="application/ld\+json"'
curl -sS -o /dev/null -w '%{http_code}\n' https://www.codeiy.com/workbench
curl -sS -o /dev/null -w '%{http_code}\n' https://www.codeiy.com/editor-preview/seo-audit
```

如果边缘返回的 robots.txt 暂时缺少 Sitemap 声明，先对照源站文件和 Cloudflare 的缓存状态。sitemap 返回 503 时先排查 Gin 与 H5 的连接。模拟爬虫被 Cloudflare 拒绝时，记录请求标识和 HTTP 状态，结合边缘日志核查平台的真实抓取。[公网基线](架构实现核验.md#2026-11-20-公网发布与搜索验收)

## 备份与恢复

广州制作库的日常备份由 K3s 运行校验，采集器将回执写入制作库的 `backup_runs`。采集延迟时，检查 `backup-report` Job、到广州的 Mesh 连接和备份 Job 的日志。[K3s 备份运维与回执](../deploy/pg-backup/README.md)

PostgreSQL、归档、媒体和 Pi 状态要对应同一恢复点。下面是**维护窗口**的备份示例，会暂时停止业务进程。目标目录放在仓库外的挂载盘；执行前确保没有其他客户端向此库写入。

```sh
backup_dir="$HOME/player-backups/$(date +%Y%m%d-%H%M%S)"
mkdir -p "$backup_dir"
docker compose stop sync api research-agent
docker compose exec -T postgres pg_dump -U anime -d anime_knowledge -Fc > "$backup_dir/knowledge.dump"
docker run --rm --volumes-from "$(docker compose ps -aq api):ro" -v "$backup_dir:/backup" postgres:17-alpine tar -czf /backup/archive.tgz -C /var/lib/knowledge/archive .
docker run --rm --volumes-from "$(docker compose ps -aq research-agent):ro" -v "$backup_dir:/backup" postgres:17-alpine tar -czf /backup/media.tgz -C /media .
docker run --rm --volumes-from "$(docker compose ps -aq research-agent):ro" -v "$backup_dir:/backup" postgres:17-alpine tar -czf /backup/research-state.tgz -C /state .
docker compose up -d
```

恢复演练使用独立 Compose 项目名、独立宿主机端口和空卷。先只启动 PostgreSQL，通过 `pg_restore --exit-on-error --no-owner -U anime -d anime_knowledge` 导入 dump；将三个 tgz 解包到对应新卷的根目录，保留文件权限。匹配源码提交与分集配置，通过环境单独提供密钥。先启动 API 核对已发布范围、旧章节锚点、肖像及入选图能否读取，再恢复 Agent、sync 和 H5。上游快照只能重建来源投影，不能恢复丢失的定稿与原图。
