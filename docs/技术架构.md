# 技术架构

**下一阶段（待建设）** 将 Gin、数据服务、Pi Durable 和图片库集中到广州。图片二进制由 Rust / Axum / libvips 服务管理，PostgreSQL 保存资产元数据与发布引用。阿里云网关通过 Mesh 分流，硅谷提供按需模型出口。[目标技术图](diagrams/media-platform.svg) · [图片库、AI 与 R2 切换](图片库架构.md)

## 两条请求链

**读者打开场景。** `/work/$work/scene/$slug` 的 loader 通过共享客户端请求 Gin。Gin 解析已发布场景、人物和章节，返回 `return_to.href`。章节的冻结正文中有同名 `passage-*` 锚点。修改回跳时一起检查 SQL 返回值和实际 SSR 段落。[共享协议](../packages/shared/knowledge.ts) · [阅读组件](../apps/web/src/features/worlds/pages.tsx)

**数据服务推进一集。** Worker 以研究 run UUID 请求 `POST /internal/research/{uuid}/collect` 和 `/write`。Agent 按 run 打开持久会话；Go 校验来源、句子位置和段落。媒体步骤通过 `POST /internal/media` 查询或启动同一持久任务。Worker 根据 running、done 或 failed 回执写步骤、返工或终止。最后由 Go 事务冻结正文、锚点、选图并设置可见范围。[取证协议](../apps/api/internal/knowledge/research.go) · [媒体协议](../apps/api/internal/knowledge/media.go) · [范围定稿](../apps/api/internal/knowledge/acceptance.go)

## 公开页面与索引

H5 从 Gin 读取首页已发布作品列表，再读取作品详情的章节、角色和场景链接。sitemap 在请求时生成，筛选标准作品路由并去重。公网页面使用 https://www.codeiy.com 上的原路径作为 canonical，SSR 输出 JSON-LD 和面包屑。分集导读以文章描述，并关联对应集号。场景条目链接到原章节的段落锚点。[sitemap 路由](../apps/web/src/routes/sitemap%5B.%5Dxml.ts) · [页面元信息](../apps/web/src/features/seo/world.ts)

工作台和编辑预览在应用内声明 noindex 和 nofollow，公网入口对这些路径返回 404。sitemap 包含首页、三个发现目录和标准作品路由。发现目录由 Gin 的 `GET /api/v1/knowledge/discovery` 一次聚合已发布的作品、人物、章节和场景。[robots.txt](../apps/web/src/routes/robots%5B.%5Dtxt.ts) · [公网入口](../deploy/player-ingress.conf)

## 持久化边界

| 数据 | 权威位置 | 读写约束 |
| --- | --- | --- |
| 来源、canonical 作品、关联、质量与治理 | PostgreSQL | worker 先暂存再归并；管理写入带操作者和原因 |
| 选题、研究、候选、验收与定稿 | PostgreSQL | 公共内容由发布视图决定；已发布段落和选图保留版本 |
| 私有试稿计费 | Gin 接受账户授权，PostgreSQL 保存费率版本、订单、余额流水及供应商账单 | H5 同源接口用短期会话访问 Gin，reader-orders 从数据库领取读者订单并交付，数据服务补做结算，Gin 只向购买账户交付图片。[资金与对账流程](模型用量与计费.md) |
| 模型调用与供应商用量 | PostgreSQL 的 `model_calls` 与去重视图 | Pi 先写本地回执，数据服务确认入库；Go 判同单独入账。[配置、回执与计费设计](模型用量与计费.md) |
| 研究对话与媒体任务检查点 | `research-state` 下的 SQLite 文件 | Pi 在启动时 resume，业务侧用同一任务身份查询结果 |
| 上游原件、入选场景衍生图 | `knowledge-archive` | 按摘要定位；Gin 通过发布记录校验场景图可见性 |
| 候选原图、手机预览及肖像衍生图 | `media-assets` | Agent 写，数据服务核验，Gin 提供文件读取 |
| 策划素材与浏览器进度 | 仓库静态资源、浏览器本地存储 | 与 PostgreSQL 定稿分别维护 |

Jev 当前用于可选的作品判同评估；图片初检与二次复核使用 Agent 配置的视觉模型。Pi 还注册了经 Gin 读取作品的工具；Compose 中运行这类工具前需给 Agent 配置可达的 `KNOWLEDGE_API_URL`（容器内可用 `http://api:4311`）。分集研究工具直接访问选题来源。[判同实现](../apps/api/internal/knowledge/match_ai.go) · [Pi 知识工具](../apps/agent/src/knowledge.ts)


## 跨环境的数据边界

广州 PostgreSQL 保存制作事实、模型回执和五维验收。硅谷的 reader-release 取出已登记上线的单集，向阿里云强制命令接收器交付定稿及入选图片。阿里云维护独立的读者库、内容寻址的图片和投递回执；H5 与 iOS 读取同一公开投影。工作台从制作库查询每次投递和公网校验结果。[传输与校验](../apps/api/cmd/reader-release/send.go)

备份节点的 Kubernetes CronJob 以只读角色取得一致性快照。pg_dump、恢复验证与按日保留由备份节点负责，恢复库不参与线上读写。调度与连接拓扑见[部署架构](部署架构.md)和[备份脚本](../deploy/pg-backup/backup.sh)。
