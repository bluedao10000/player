# 从 H5 两条阅读路径接入 PostgreSQL

设计评审稿 · 2026-11-18。以下表和接口是提案；“已有”指当前代码或本地只读查询已经核实的部分。

## 1. 先确定两条读路径

| 用户操作 | 潮汐邮局 | 星际牛仔 | 必须由库回答的问题 |
| --- | --- | --- | --- |
| 首页点作品 | 潮汐邮局 → 白帆港夜间邮路 | 星际牛仔 → 初识赏金猎人 | 哪些作品世界已发布？哪两部在首页展示？ |
| 作品点角色 | 阿澪 | 斯派克 | 此人在这个版本里是谁？ |
| 角色点出场章节 | 《末班渡船》 | 第 1 集 Asteroid Blues | 哪些可读章节有这个人出场的依据？ |
| 章节点场景 | 旧渡口核对名册 | 两人走进酒吧 | 这章的哪一幕、谁在场？ |
| 场景回到故事 | 原创短篇第 2 段 | 站内分集导读第 2 段 | 返回哪份公开正文、哪个稳定锚点？ |

章节可以只有目录，或有正文但尚未整理场景。一章可以发布多幕。导读线顺序、官方集序、正文段序分别存储。场景标题可以是站内拟题，返回的落点是 H5 文字段落；原作画面时间码有独立证据时再提供。

## 2. 现有底座与边界

- **已有 PostgreSQL。** `works.id` 标识作品版本；`work_titles`、`work_sources` 管别名与外部身份。已有来源、版本、同步运行、staging、快照、作品匹配和质量检查。`work_relations` 是从外部 URL 推导作品间关联的视图。现有关系不包含角色出场或场景。 [初始表和视图](../../apps/api/internal/knowledge/sql/001.sql) · [作品投影](../../apps/api/internal/knowledge/projection.sql)
- **已有 Gin / pgx。** 保留 `GET /api/v1/knowledge/works?q=…` 和 `/works/:id` 的 UUID 语义与分页协议。TanStack Start 与 Agent 已有共享知识库客户端。新增读取方法即可。 [Gin 路由](../../apps/api/internal/knowledge/api.go) · [共享客户端](../../packages/shared/knowledge.ts)
- **这次本地核对。** 原创名称“潮汐邮局”未查到作品记录。《星际牛仔》TV 版 UUID 为 `31bc5bf8-4691-493e-8b11-6524a7ef0fa9`，1998 年，26 集，Bangumi ID 为 `253`。同库还有剧场版、特别篇，各有独立 UUID。UUID 用于本地验收；不同数据库导入时用外部身份定位 TV 版。 [本地 TV 版资料](http://127.0.0.1:4310/knowledge/31bc5bf8-4691-493e-8b11-6524a7ef0fa9)
- **仍是前端样板。** 当前每章只有一个 `scene`，回跳依赖 `paragraph` 数组下标；原创复用旧角色页和故事页。角色页列了四篇阿澪出场作品，作品世界只精选其中两篇。接库时应保留这一区别。 [样板关系](../../apps/web/src/features/worlds/catalog.ts) · [原创目录](../../apps/web/src/features/post/catalog.ts) · [阿澪角色页](../../apps/web/src/features/post/character.tsx)

## 3. PostgreSQL 表结构草案

沿用 pgx 与 SQL migration。作品继续使用现有 UUID。除下表注明的复合键外，新实体使用 UUID 主键。公共子实体带 `work_id` 外键和 `UNIQUE(work_id,id)`，子实体间引用使用复合外键。公开 slug 稳定，改显示名不改地址。

### 3.1 读者看到的实体和关系（新增）

| 表 | 核心字段 | 主键以外的重要约束或用法 |
| --- | --- | --- |
| `work_worlds` | `work_id uuid PK/FK works, slug text, origin text, display_title text, edition_label text, intro text, hero_asset_key text NULL, published_at timestamptz NULL, revision bigint` | slug 全站唯一；origin 为 original / external。只列出已发布且作品 active 的世界。revision 随该作品的一次公开变更递增 |
| `home_world_slots` | `slot_key text, position int, work_id uuid FK work_worlds` | PK(slot_key,position)，同栏作品唯一。首批填现有首页「作品世界」的两个位置；Hero 的故事轮播独立 |
| `work_characters` | `work_id, id, slug, display_name, role_text, portrait_asset_key NULL, evidence_id` | UNIQUE(work_id,slug)。身份以作品版本为范围；人物名称和译名不是主键 |
| `work_chapters` | `work_id, id, slug, kind, title, intro, season_no int NULL, episode_no int NULL, read_state, evidence_id` | kind 为 short_story / episode；read_state 为 catalog_only / readable。TV 正集在本作内按 season_no、episode_no 部分唯一，两项须同时有值；独立短篇可无编号。UNIQUE(work_id,slug) |
| `work_storylines` / `work_storyline_chapters` | 线含 `work_id,id,slug,title,kind,intro,evidence_id`；成员含 `work_id,line_id,chapter_id,position` | kind 区分 editorial_guide / canonical_arc；成员 PK(work_id,line_id,chapter_id)，UNIQUE(work_id,line_id,position)。同一短篇可入多条线 |
| `chapter_blocks` | `work_id,chapter_id,block_key text,position int,body text,content_kind,evidence_id` | PK(work_id,chapter_id,block_key)，章内 position 唯一。block_key 是持久编辑标识，重排只改 position。正文标明 original / editorial_guide |
| `work_settings` | `work_id,id,slug,kind,name,parent_id NULL,evidence_id` | 地点可形成“白帆港 → 旧渡口”；职业设定可收录“赏金猎人”。首轮地点随场景返回，词条独立页可后续开放 |
| `work_scenes` | `work_id,id,chapter_id,slug,title,summary,position,setting_id NULL,return_block_key,evidence_id` | slug 在作品内唯一；章内幕序唯一。外键 (work_id,chapter_id,return_block_key) 必须指向本章段落；额外 UNIQUE(work_id,chapter_id,id) 供幕内人物引用 |
| `chapter_appearances` | `work_id,chapter_id,character_id,evidence_id` | PK(work_id,chapter_id,character_id)；反查索引 (work_id,character_id,chapter_id)，供“出场章节”读取 |
| `scene_appearances` | `work_id,chapter_id,scene_id,character_id,evidence_id` | PK(work_id,scene_id,character_id)。分别复合引用本章场景、本章出场记录。证实在场可以补一条本集出场记录；反向推导禁止 |

索引优先服务实际查询：作品内 slug 唯一索引用于直达，`(work_id,chapter_id,position)` 用于顺序读段落和场景，专题成员索引用于导读顺序。资料不足的角色或幕内关系可以留在候选区。无授权图片时沿用当前《星际牛仔》的排版封面。

### 3.2 数据服务需要的记录（新增或扩展）

| 对象 | 结构及用途 |
| --- | --- |
| 来源登记（扩展） | 为已有 `knowledge_sources` 增加处理类别，如 `work_snapshot / original_manifest / enrichment`。既有两源默认 work_snapshot。调度先按类别分发；仅旧类型走当前全量作品合并。现有检查器与解析器需要新增适配器 |
| `world_evidence` | `id bigint PK, source_version_id bigint FK knowledge_source_versions, document_key, locator, content_hash, source_uri, attribution, usage_kind`。UNIQUE(source_version_id,document_key,locator,content_hash)。证据固定到不可变版本和局部位置，如官方第 1 集简介或原创清单中的某一段。来源变化生成新证据 |
| 实体身份映射 | 分开设 `world_character_keys`、`world_chapter_keys`、`world_scene_keys`。各含 `source_id,work_id,external_key,对应实体_id`，PK(source_id,work_id,external_key)；复合 FK 到类型正确的实体。上游有 ID 就用 ID，自有内容用永久编辑键。中文译名和抓取顺序都不能承担去重 |
| `world_enrichment_jobs` | `id,work_id,source_id,task_kind,input_fingerprint,status,attempts,next_attempt_at,lease_until,run_id,last_error`。UNIQUE(work_id,source_id,task_kind,input_fingerprint)；指纹包含输入版本和规则／抽取器版本。按 status、next_attempt_at 领取，用可续租的任务避免宕机后永久占用 |
| `staging_world_facts` | `job_id,fact_key,predicate,subject_key,object_key NULL,payload jsonb,evidence_id,decision,reason`，PK(job_id,fact_key)。接收人物、章节、出场边、段落与锚点候选。判断分为 accepted / unresolved / rejected，记录候选模型和规则版本；工作台可查未通过的具体原因 |

已核实的事实或正文至少指向一条主证据，额外佐证可保存在同一事实对应的候选记录中。来源版本复用现有 `knowledge_source_versions` 和 `knowledge_sync_runs`；详情来源以每份文档或固定文档集合的清单哈希作版本，保留可合法留存的快照、定位和归属信息。用于元数据、独立撰写导读、可展示原文和图片的许可分别判断。页面只返回可公开的归属信息。

**发布单位选一部作品的一次完整修改。** 下载、解析、写 staging 和可选 Agent 调用先完成。数据服务再取得该作品的事务锁，核对基础 revision，按键 upsert，检查跨表约束、正文与回跳目标，更新 revision 和运行结果并一起提交。相同输入无变更时不递增 revision。某个有歧义的事实可继续等待；依赖它的阅读路径不发布。已有公开路径的替代版本缺任何一环，就保留原路径。超时或只抓到部分网页不能触发全量删除。明确撤回的关系通过同一事务连同受影响的引用更新；明确撤销展示授权的内容立即停止公开。

## 4. 两种入库方式

### 潮汐邮局：平台原创清单

1. **一次导出，再以清单维护。** 从原创目录、人物页和作品样板整理一份带 schema 版本的 UTF-8 清单。固定键如 `original:tidepost`、`character:mio`、`story:last-ferry`、`scene:ferry-register`、`block:missing-ticket`。四篇已有短篇入库，“白帆港夜间邮路”只选两篇；清单单独标明正文、导读编排、角色立绘资产和许可。互动选项、玩家选择与私人对白不进入作品事实。
2. **给原创作品自己的来源。** 数据服务读取受控版本的清单，以清单内容哈希判变，创建自有来源版本。首次分配作品 UUID，同时在现有 `knowledge_source_records` 写入该自有来源的作品级 active 记录，贡献标题、原创身份引用和别名，保持记录的归一化格式与现有投影兼容。随后按稳定键写世界内容。外部来源删除或同名匹配不得接管自有身份；只有自有来源的显式撤回才能撤掉这份贡献。这样现有投影重算时仍有有效来源支撑。原创短篇集的类型需在知识库质量规则中明确支持，避免被现有动画枚举反复报错。
3. **保住旧 URL 和段落。** `/character/mio`、`/story/last-ferry` 保留，SSR loader 改调同一组作品世界接口。清单把“船票少了一张”这段赋给 `missing-ticket`，场景持有该键。渲染时在该段输出现有 `passage-ferry-register` 锚点；若一段对应多幕，为同段输出多个锚点。插入一段前言后回跳位置仍正确。

### 星际牛仔：定时补充外部资料

1. **先锁定版本。** 数据服务按 `work_sources(provider='bangumi', external_id='253')` 定位，核验唯一的 TV / 1998 结果。多解或冲突保留候选。作品级快照仍由现有 anime-offline-database 和 bangumi-data 管；下列 Bangumi API 是新增的详情来源。
2. **拿目录和人物身份。** 实测 Bangumi 分集接口前两条的 ID 为 `519`、`7027`，集序 1、2；作品人物接口返回斯派克 `77`、杰特 `78`。新适配器分页取正片目录，按外部 ID upsert，过滤 SP、电影。目录可以有 26 集，首批只为完成资料校验的前两集开放阅读。人物接口只支持“属于本作”这条边。 [分集样例](https://api.bgm.tv/v0/episodes?subject_id=253&type=0&limit=2) · [作品人物](https://api.bgm.tv/v0/subjects/253/characters)
3. **从局部资料建立出场边。** 用官方人物页、分集简介核对身份和局部事件。第 1 集摘要支持“斯派克、杰特追捕阿西莫夫”，也支持“阿西莫夫和卡特琳娜到酒保的店”。可以据此建立四条本集出场记录，酒吧场景的样板人物两位。某个角色缺 provider ID 时先用该作品范围内的官方来源键，待获得同一身份的证据再补映射。 [官方分集简介](https://www.cowboy-bebop.net/story/) · [官方人物资料](https://www.cowboy-bebop.net/character/)
4. **生成可读内容。** 以事实写站内中文导读，给段落稳定键 `bar-deal`；`bar-visit` 这幕关联该段及两位角色。“两人走进酒吧”和“初识赏金猎人”分别标为站内拟题和编辑导读。样板文字可以作为待核对草稿。模型如参与抽取或润色，由数据服务委派 Pi Durable，返回候选与证据位置；数据服务验证实体、出处及许可后自动发布。材料只证实整集、无法确定某幕人物时留空待补，下一轮有新证据再判。
5. **独立推进和观测。** 腾讯云数据服务按缺项生成任务，并定期探测详情来源版本，即使基础作品版本未变也能发现新分集资料。限流按来源退避并尊重 Retry-After。工作台按作品展示“已取得目录 / 可读章节 / 有正文落点的场景”、未决关系、失败原因和最后成功发布时间。阿里云 Gin 读取 PostgreSQL 已发布内容；一次 H5 请求无需等待跨云抓取或模型调用。

## 5. Gin 读接口与 H5 对接

新增端点均在 `/api/v1/knowledge` 下。工作台沿用独立运行记录；发布写入仅由数据服务执行。每个 SSR 页面一次聚合读取，通过一条 SQL 或只读可重复读事务返回同一 revision。

| GET 路径 | 给哪个页面 | 最小响应契约 |
| --- | --- | --- |
| `/worlds?placement=home` | 首页两个作品入口 | `items[{work_id,slug,title,edition_label,href,hero_asset_key}]`，按槽位排序。空列表返回 200 |
| `/worlds/:work` | 作品世界 | `work,revision,characters[],storylines[{title,kind,chapters[]}],scenes[]`。子项只给标题、排序和 href，首页不预加载所有正文 |
| `/worlds/:work/characters/:person` | 阿澪／斯派克角色页 | `character,work,appearances[{chapter_id,title,label,read_state,href}]`。只查 chapter_appearances；短篇按导读顺序及稳定后备排序，TV 按官方集序。只有目录的章节可展示，href 为空 |
| `/worlds/:work/chapters/:chapter` | 原创阅读／分集导读 | `chapter,work,content_kind,blocks[{key,text,anchors[]}],scenes[{slug,title,href}],attribution[]`。同一块可承接多条链接，文字内容在 SSR HTML 中输出 |
| `/worlds/:work/scenes/:scene` | 具体一幕 | `scene,work,setting,scene_cast[],return_to,attribution[]`。人物只查 scene_appearances；回链由服务端从所属章和段落生成 |

下面是相同接口在两条路径上返回的关键字段，省略与点击无关的元数据。

| 场景响应字段 | `tidepost/scenes/ferry-register` | `cowboy-bebop-tv/scenes/bar-visit` |
| --- | --- | --- |
| `scene.title` | 旧渡口核对名册 | 两人走进酒吧 |
| `scene_cast[].name` | 阿澪、渡船船长 | 阿西莫夫、卡特琳娜 |
| `return_to.block_key` | missing-ticket | bar-deal |
| `return_to.href` | `/story/last-ferry#passage-ferry-register` | `/work/cowboy-bebop-tv/chapter/asteroid-blues#passage-bar-visit` |
| 阅读页对应块的 `anchors[]` | `["passage-ferry-register"]` | `["passage-bar-visit"]` |

公共 href 统一由路由映射生成：潮汐邮局已上线的原创章节和阿澪复用旧地址，其余走作品范围内的 URL。所有子项按 work_slug 与 child_slug 同时查；跨作品拼接、未发布世界或不可读正文返回 404，数据库不可用返回 503。目录中已发布但暂无场景的章节正常返回空数组。H5 按真实空态展示。已有 UUID 资料接口可新增可空的 `world_href`，让知识库搜索也能进入已开放的世界。

## 6. 切换与验收

先新增表、适配器、只读接口，旁路跑完两批样板；对比现有静态页与 API 的节点、顺序、人物、正文和锚点。验收通过后按作品切换 SSR loader。首页仅切换「作品世界」栏；原有收藏键、故事 slug、私人会话与 Hero 轮播无需迁移。两部作品切换成功后再移除对应的前端事实副本。

| 验收用例 | 预期 |
| --- | --- |
| 阿澪 → 末班渡船 → 旧渡口核对名册 → 回到故事 | 旧地址可直达，SSR 命中原文；给正文前插一段仍回“船票少了一张” |
| 斯派克 → 第 1 集 → 酒吧 → 回到故事 | 本集有斯派克，酒吧人物只有样板两位，返回导读中讲交易的一段；剧场版不混入 |
| 一章两幕、一段承接两幕 | 章节列两项，各有独立 URL；每个旧场景链接都能命中有效锚点 |
| 详情来源 429／断网、证据矛盾、重复导入或并发重试 | 保留前次完整路径；能在工作台看到待补或失败；幂等重跑不增加实体/关系，旧批次不能覆盖新 revision |
| 原创遇到外部同名记录、外部快照撤回 | 自有身份、来源贡献及公开路径仍在。外部数据撤回按自己的来源范围处理 |
| 关闭 JavaScript，屏蔽上游与 Agent | 两条路径均可从本地 PostgreSQL 经 Gin 读完；跨作品子路径返回 404 |
