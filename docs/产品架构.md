# 二次元角色扮演与剧情推进 · 产品架构 v0.1

面向喜欢追人物、读设定、写同人的小众读者。H5 用可搜索的角色、故事和设定吸引首次访问；读者在感兴趣的一幕参与剧情，下次回来可以接着上次的选择继续。iOS 延续同一套内容身份、起点与个人进度。

## 一次完整体验

以原创世界「潮汐邮局」为例。读者搜索“潮汐邮局的夜班邮差”，落到角色「阿澪」的公开页，在人物简介下读到短篇《末班渡船》。文末的“从码头这一幕开始”把读者带到明确的时间、地点和角色。读者选择“拆开退回的信”，阿澪认出邮戳，下一幕的目标变成寻找旧灯塔。这个选择只写进读者自己的时间线。

编辑可以独立委托 Agent 写一篇码头番外。读者也可以选取自己愿意分享的一幕，预览摘编后提交给编辑。两种来源进入同一审核队列，发布后才产生可被搜索和引用的页面。

## 页面与入口

H5 主导航为发现、角色、故事、我的。发现首屏展示编辑选出的短篇与剧情片段，其次展示角色和世界专题。读者可以通过普通链接在角色、故事、百科之间往返。首次阅读匿名；首次参与剧情时签发游客身份。

| 页面 | 读者在这里得到什么 | 下一步 |
| --- | --- | --- |
| 首页 /，角色与故事列表 | 按主题浏览精选内容、角色与连载，分页有独立 URL | 阅读一个条目 |
| /character/{slug} | 一句话认识人物，查看别名、所属作品、关系和出场故事 | 读代表作，或与该角色开始冒险 |
| /story/{slug} | 摘要、完整短篇或章节、出场角色、前后篇 | 连续阅读，或从指定场景进入 |
| /scene/{slug} | 可独立阅读的一幕，标明背景、参与者与故事出处 | 回到原篇，或从这一幕开始 |
| /world/{slug}、/wiki/{slug} | 世界规则、地点或有来源的术语解释 | 顺着作品、角色与设定内链探索 |
| /play/{sessionId}、/me | 私人剧情、可选行动、自由输入、上次进度 | 提交一个行动、续玩或回到公开内容 |
| /admin、/preview | 编辑草稿、检查来源、预览变更和审核发布 | 发布、回滚或撤回 |

公开内容走完整 SSR。个人区、互动、预览和管理页鉴权并返回 noindex、private/no-store；私有资源每次校验所有者或编辑权限。

## 服务与数据所有权

| 服务 | 职责与接口 | 本地存储 |
| --- | --- | --- |
| TanStack Start · apps/web | React + TanStack Router 输出 H5。服务端 loader 读取已发布快照；正文与 head 就绪后先发送，关联推荐通过 Suspense 流式返回。浏览器请求走同源 /api。 | 只持有页面展示状态 |
| Gin · apps/api | 公开读取、内容与角色卡 CRUD、审核、游客和权限、会话与消息转发、索引和事件。唯一可提交业务事实的服务。 | data/app.sqlite |
| Pi Durable · apps/agent | 按任务读取限定版本与范围的资料，调用 OpenAI 兼容模型，提交候选草稿或回合结果，恢复中断任务。 | data/agent.sqlite，单写进程 |

读者访问公开内容只走 Web → Gin → 已发布快照，模型故障时仍可阅读。开发期两份 SQLite 分开管理。Gin 的查询与迁移由 repository 层承载，迁移 PostgreSQL 时验证唯一性、事务锁、JSON、时间和分页语义。Pi 的运行存储独立升级。

## 内容生产与发布

| 实体 | 关键字段与约束 |
| --- | --- |
| Content | 稳定 ID、类型、slug、公开性、published_revision_id；同类型 slug 唯一，旧 slug 留重定向 |
| ContentRevision | 不可变版本，标题、摘要、Markdown、标签、作品与角色关联、作者、来源、创作类型、实质更新时间；清理渲染后的 HTML |
| Character / CharacterCardVersion | 公开身份与角色卡分别查询。卡保存说话风格、目标、知识边界和开场设定；公共 DTO 只列公开字段 |
| Work / World / KnowledgeChunk | 作品、创作世界线、来源 ID、文本片段和知识版本；区分原作事实、同人设定、私有剧情 |
| Session / StoryState / Turn | owner、角色卡与开场快照、独立 Pi conversation、活动命令、状态版本、地点、关系、物品、目标和伏笔 |
| GenerationJob / Outbox | 持久任务、操作键、预期版本、投递状态、结果 ID；驱动重试及完成通知 |

人工创作与 Agent 产物依次进入草稿、待审、发布。编辑修改线上文章时从已发布版本新建修订，访客继续读旧版。发布事务切换版本指针并记录发布事件，列表和 sitemap 随之更新。撤回后公共接口停止提供正文；回滚指向已有的审核版本。

私聊摘编需用户主动选择和确认，移除个人信息与私有设定后供编辑审核。公开的来源字段只列可披露资料，内部保留摘编与回合的追溯记录。

## 剧情、模型与知识

**生成故事。** 编辑指定角色、世界版本、主题与体裁。Agent 检索资料，产生标题、摘要、正文、关联对象和来源引用；Gin 按 schema 校验并幂等落为草稿。模型密钥、base URL、模型 ID 与模型兼容选项留在 Agent；到阶段 5 分别验证聊天/工具与 embedding 能力。

**推进一回合。** 创建会话时固定角色卡、场景、世界、提示词版本与知识快照，每个会话分配独立 Pi conversation。客户端发送行动与幂等键；Gin 在同一事务内保存用户消息、活动回合与 outbox，返回 202。投递器用 command_id 作为 Pi requestId。Agent 输出 narration、dialogue、beat_progress、choices、state_patch。例如“认出旧邮戳”是新事实，“找到灯塔看守人”是新目标。

Gin 按操作键先查历史提交，再验证载荷哈希、活动命令与预期状态版本；最终消息、状态和完成事件一起提交。同一会话同时仅接纳一个新回合。SSE 传递进度与完成事件，重连按事件游标补读或取最终快照。Agent 以业务确认的回合作为下一轮上下文。进程重启时重开存储、resume 并重投未确认任务，模型请求可能再次计费。

**导入与检索。** 固定 anime-offline-database 快照、哈希和许可，先导入作品元数据、别名与外部引用；用来源 ID 幂等 upsert。人物设定、剧情与图片分别补齐来源和使用依据。导入条目由编辑选择是否制作公开内容。KnowledgeRetriever 先按作品、世界线、版本及 owner/session 过滤，再对小样本 embedding 算余弦相似度，以关键词和别名兜底。向量记录模型与维度，后续可替换 pgvector。会话记忆只参与本会话检索。

## API 与协议

| 调用者 | 计划接口（/api/v1） | 约束 |
| --- | --- | --- |
| 匿名读者、SSR | GET /contents、GET /contents/{type}/{slug}、GET /public-index | 游标分页；同一发布快照提供正文、关系与 SEO 字段 |
| 编辑者 | POST /contents、PATCH /contents/{id}、DELETE /contents/{id}、POST /contents/{id}/publish 或 /withdraw | 编辑产生新修订；删除归档并撤回；检查角色和版本 |
| 编辑者 | POST /characters/{id}/cards、GET /characters/{id}/cards/{version}、POST /generation-jobs、GET /generation-jobs/{id} | 角色卡版本和生成任务可追溯 |
| 游客 / 用户 | POST /guests、POST /sessions、POST /sessions/{id}/messages、GET /sessions/{id}/state 或 /events | 服务端身份绑定 owner；稳定幂等键；事件支持续传 |
| 内部 Agent | 提交 draft 或 turn-result、查询命令提交结果 | 服务身份鉴权；同操作同载荷返回原结果，载荷冲突返回 409 |

跨语言协议以 JSON Schema / OpenAPI 约束；共享稳定字符串 ID、UTC 时间、schema_version 与错误码。阶段 1 仅提供 GET /healthz 和共享健康响应契约。公开索引接口与业务接口按后续阶段落地。

## 搜索、引用与增长

- 公开内容首次响应就包含标题、可读正文、摘要、内链和 canonical。meta、OG、Twitter 与 JSON-LD 引用同一 revision。角色用 WebPage + Person，短篇用 ShortStory，百科用 Article，面包屑用 BreadcrumbList。
- sitemap 从公开、已发布、允许索引的 canonical 集合生成，lastmod 取实质修改时间。缺失页返回 404，旧 slug 301 到新地址；撤回同步移出内容流和 sitemap。首版公开 HTML 按请求取发布状态，静态资源可长缓存。
- 人物与术语页首段直接交代“是谁、出自哪里、与谁相关”，正文链接到具体设定与资料来源；清楚标注原创、同人与原作。上线后分别观察搜索收录和可辨认的 AI 引用流量。
- 以匿名入口和 content_id 统计搜索落地 → 关联阅读 → 点击进入剧情 → 首个已提交回合 → 七日续玩。用“完成首回合的会话数 / 新建会话数”判断入口到开场是否顺畅，用“已发布且有自然访问的页面数”判断内容选题。分析事件仅记录标识与来源。

## H5 与 iOS

H5 先实现移动端阅读与剧情恢复。阅读组件通过 DTO 渲染，身份、存储、外链和深链由平台适配。未来 apps/ios 可用 Capacitor 包装静态 React 客户端，共用 Gin API 和公开内容 ID；服务器持续运行 Start SSR。Universal Links 把相同 canonical URL 映射到 App 阅读或 H5 回退。首版交付范围为 H5，客户端扩展仅面向 iOS。

## 八阶段验收

| 顺序 | 交付 | 通过条件 |
| --- | --- | --- |
| 1 · 服务骨架 | workspace、Start SSR、Gin、Pi Durable、两份 SQLite、共享健康协议 | 三服务健康，原始 HTML 有服务端标题；类型检查与构建通过 |
| 2 · 内容站 | 原创 fixtures，内容流、角色详情、故事阅读、基础 meta | 手机正常阅读；关闭 JS 后可从首页读到角色与故事；curl 可见正文与 head |
| 3 · 内容 API | Gin 内容 CRUD、角色卡版本与编辑权限 | 增改查删走真实 API；公开响应只含已发布字段，越权被拒绝 |
| 4 · 数据流 | SSR 读取业务库，补片段、世界与百科路由，导入作品快照 | 更新发布版本后原始 HTML 变化；重启保留；重复导入作品数稳定 |
| 5 · 最小 Agent | 从角色设定检索知识、生成独立剧情片段 | 真实兼容端点输出符合 schema；强杀重启、重投同命令可恢复 |
| 6 · 内容沉淀 | Agent 草稿、编辑预览、审核发布 | 发布前匿名不可访问；发布后 URL 返回对应版本；可撤回 |
| 7 · 私有互动 | 从角色或场景进入，游客身份、剧情状态、SSE 与恢复 | 两位读者剧情隔离；断线、重复消息、提交响应丢失均只确认一个回合 |
| 8 · SEO 与 GEO | 完整 meta、结构化数据、sitemap、旧链、观测 | 爬取公开链接闭环，校验 JSON-LD、301、404、撤回和索引一致性 |

首版演示建议集中在同一原创世界，准备三个角色、三篇故事及其关联场景，优先跑通一条“匿名阅读 → 进入场景 → 完成回合 → 审核摘编 → 新公开页”的路径。每阶段验收后再决定是否进入下一阶段。
